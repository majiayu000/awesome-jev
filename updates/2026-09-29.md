## 值得一看的工具（优先）

1. **[lzq-0529/jev-span](https://github.com/lzq-0529/jev-span)**（约 3★；PyPI [`jevspan`](https://pypi.org/project/jevspan/) 0.1.0，约 2026-09-28）  
   把 Jev 的 Choice 流水线做成**零样本 NER**：标点切窗 → 提名 → 校验 → 边界抛光 → 文档内传播；每实体带概率与 `--trace` 决策树。作者在 12 个中英 / CrossNER 集上自报严格 F1 均值约 **73.7**（同类型描述下略高于直接抽取的 Qwen3.8-27B）。中文优先、schema 可换药名/法条等类型。相对 09-21 `jev_jsonschema` / 09-28 jevgrep：本项是**抽取形态**，不是 grep / schema 桥。

2. **[fabianboth/jevpipe](https://github.com/fabianboth/jevpipe)**（约 4★；PyPI [`jevpipe`](https://pypi.org/project/jevpipe/) 至 0.2.1，约 2026-09-27–28）  
   Unix 管道式批量判断：`filter`（类 grep 的 yes/no）与 `map`（多题 JSON），stdin / 文件 / `--read-files`；OpenRouter 或 TypeSafe；附 coding-agent skill。适合「上千行日志 / 提交说明 / 文件路径」的规模化分流，而不是单次交互 playground。相对 09-28 jevgrep（仓库语义入口）与 09-21 CLI 族：偏 **shell 流水线吞吐**。

3. **[Ice-Hazymoon/jevlint](https://github.com/Ice-Hazymoon/jevlint)**（约 15★；[V2EX](https://www.v2ex.com/t/1244562)）  
   语义 lint：`ast-grep` 预筛 + 自然语言规则问 Jev（带缓存），面向传统 lint 写不出的「日志是否泄密」类问题；配置形态接近 eslint。相对 09-24 [`doronp/jevc`](https://github.com/doronp/jevc)（规则→窄证据题编译器）与各类 PreToolUse gate：本项落在 **CI / 本地审查引擎**，不是 agent hook。

## 评测 / 负结果（增量）

1. **[arXiv:2609.29769 · Jev vs. LLMs as Rubric Judges…](https://arxiv.org/abs/2609.29769)**（UPenn，提交约 2026-09-24；09-28 稿未收录）  
   九个 panel、约 5003 对：Jev 与三家 flash-tier LLM judge 在相同准则文上对比。二值 checklist 上常接近或更优且便宜约 **29–325×**；分级量表上多落后于最强 LLM judge，且**四家 judge 彼此更一致、却共同低于人类标签**（偏低估等级）。自信错误处 LLM 约 **96%** 复述 Jev 的错答 → cascade 主要省钱、交叉拟合增益最多约 **1.5** 点。相对 09-28 的 2609.26550（偏好/事实性 cascade）：本项是 **rubric / 量表 judge** 与相关误差上限。

2. **[dchristopoulos/jev-aita](https://github.com/dchristopoulos/jev-aita)**（约 3★）  
   770 条 Reddit AITA：Jev（直问）Brier 次于 Sonnet 5；中位延迟约 **0.39 s**，相对 Sonnet 约 **6.3×** 快、约 **62×** 便宜——**不是**厂商宣传的 40–200×（对照模型几乎不推理）。相对评论者分布时，未校准 Jev 未必稳赢基率。方法注明独立付费、协议与可重建日志。属意见标签任务，宜作「速度倍率怎么读」的负结果旁证。
