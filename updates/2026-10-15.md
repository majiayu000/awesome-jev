## 官方变化

1. **[TypeSafe · Jev 1.14「For the builders AND dreamers」](https://typesafe.ai/blog/jev-1-14)**（**10-14** 博文；文档 [Models](https://docs.typesafe.ai/models) / [Images](https://docs.typesafe.ai/images) / [Box](https://docs.typesafe.ai/primitives/box)）\
   `jev-1.14.0` 以 **`jev-preview`** 别名上线，价格与默认上下文不变（输入 $0.042 / 百万 token、输出免费；64k 每请求 / 32k 每题）；官方定位是「各处小幅改进」，预计**多语言**提升最明显。三项实验特性需逐请求加 header 才开：
   - **图像**（`TypeSafe-Danger-Zone-Images: true`）：图片放进顶层 `assets`，在 `state` / `instructions` / `criteria` 里用引用字符串替换；官方说 **`jev-1.13.0` 本来就是多模态**，所以 1.13 / 1.14 都能收图。没带 header 而请求里有图或 Box 会直接 `400`。
   - **`box` 题型**：第四种题型，返回单个 bounding box（`top/bottom/left/right`，0–1 相对坐标）+ `confidence`；**只在 1.14** 可用，一题一个目标。
   - **长上下文**（`TypeSafe-Danger-Zone-Long-Context: true`）：每请求、每题上限都升到 **262k token**（1.13 / 1.14 均可），同价但更慢、更不准。

   官方明说这些「jaggedness 仍太多，不为生产背书」；**`jev-latest` 约一周后才切到 1.14**，1.13 弃用前给 60 天通知（1.14 为 30 天）。中文侧 [PANews 10-15 快讯](https://www.panewslab.com/zh/articles/01a13d18-26cd-7359-ba88-c3f2b2e1a95a) 已跟进（「上下文扩至 4 倍」即 64k→262k）。别名迁移的坑见 [踩坑 #37](../guides/gotchas.md)。

## 独立评测与负结果（优先）

1. **[RINNECODER/jev-box-study](https://github.com/RINNECODER/jev-box-study)**（**10-15** 凌晨公开；MIT；[在线 demo](https://hallucination-check.vercel.app)）\
   发布当天就用 Jev 1.14 的 Box + 图像做「AI 图片幻觉检测」，七个版本（v1–v7b）的原始分数 JSON、站点代码、两个 agent skill 全公开。作者结论：Box **在合成文档里定位植入错误很强**（拼写 98%、错百分比 97%、自相矛盾 97%，干净对照零报警），但真实 AI 图能否被标出，**更取决于问法和裁剪尺度**而不是模型本身——同一句荒谬文字在段落裁剪上 0.90、整页上只有 0.60–0.64；v1 问题里出现「hallucination / AI」会诱导 yes，8 张真实照片标了 7 张。实操坑：Box **没有「这里什么都没有」**（必须先用 noul 判存在或把低 confidence 当无）、可能回零宽框、遮罩后重问会反复回同一区域、「找任意东西」只回一个巨框。作者自述是小样本手挑图，不是基准。

2. **[rahulbansalc6414/jev-as-a-guardrail](https://github.com/rahulbansalc6414/jev-as-a-guardrail)**（**10-13** 晚；MIT；冻结 [`ANALYSIS.md`](https://github.com/rahulbansalc6414/jev-as-a-guardrail/blob/main/results/1000-run-20261013-162726/ANALYSIS.md)，上期未收）\
   输入护栏对照：Jev（3 个 noul + 1 个 choice）vs Claude Haiku 4.5（tool-use 结构化输出），1,000 条 = 533 jailbreak（Jailbreak-PromptBank）/ 133 对抗改写（Mindgard evaded）/ 334 伪有害良性（PHTest），数据集 revision 已钉。作者表：总检出 Jev **91.9%** vs Haiku **96.6%**；**对抗改写上 78.2% vs 94.0%**（最大差距，Haiku 抓到而 Jev 漏掉 32 条）；误报 Jev 9.6% 更低（Haiku 14.1%）；中位时延 328 ms vs 2,066 ms，每千次 $0.03 vs $1.87。结论很直接：Jev 当前置便宜闸可以，**单独挡对抗改写不够**。阈值固定 0.5，未做校准扫描。

3. **[gopaljigaur/system-one-bench](https://github.com/gopaljigaur/system-one-bench)**（**10-15** 公开；MIT；`results/` 含逐行输出）\
   「同一台机器、同一批行」的开放决策模型中立对照：ag_news（四选一 Choice）与 sst2（Noul）各 150 行，Apple M4，固定种子、三次预热。作者表：ag_news 上 Laya 0.4.7 **0.953**（ECE 0.028）、Laya 多语 MLX 0.920、Von 1.3 0.913 但 **ECE 0.230**；sst2 上 Von 1.3 0.847 / ECE 0.024 反超，**Laya 多语 MLX 掉到 0.527**；Llama 3.2 1B 走 ollama 生成路径在 ag_news 上 150/150 拿不到类型化答案。要点：准确率与校准不同向，同一模型跨任务排名会翻。样本小、只两项任务、未含托管 Jev。

4. **[sakhadib/literal-lock-in](https://github.com/sakhadib/literal-lock-in)**（**10-13** 晚；CC-BY-SA-4.0；含 ACL 格式论文 PDF 与逐题输出，上期未收）\
   孟加拉语习语四选一：把习语**自身的字面释义**放进选项，三个决策模型（Laya-ml 322M encoder / Lod-lille-0.6B decoder / 托管 `jev-1.13`）都被吸走。3,265 对配对题上，字面吸引率孟加拉语 **0.731 / 0.918 / 0.304**，换成配对英语题降到 0.379 / 0.241 / 0.047——各家在孟加拉语里被「锁死」程度为英语的 1.9–6.4 倍；常规干扰项下更强的 Lod-lille 一遇字面释义准确率跌到 0.066。方法点：决策模型不出文本，**选项列表就是唯一可控的干预面**。对非英语 choice 题的选项设计直接有用。

## 方法与开放模型（方法新）

1. **[sunyasheng/JevGPT](https://github.com/sunyasheng/JevGPT)**（**10-14**；Apache-2.0；论文 [arXiv:2610.18272](https://arxiv.org/abs/2610.18272)；KAUST，Schmidhuber 组；[逐题记录](https://huggingface.co/datasets/yashengsun/JevGPT-runs)）\
   研究型 agent 的双系统拆分：GPT-5.5 当 System Two 定证据目标、整合结论，`jev-1.13.0` 当 System One 并行判断每个来源是否支持、定位段落、决定是否继续读，只回原文段落。作者表：BrowseComp-Plus 830 题准确率 **90.48%**（对比 Reason-ColBERT 90.00 / RISE 89.88 / Pi-Serini 82.05），每题 91.7 s；NeuCLIRBench nDCG@20 **0.5390**。附录 B.3 更值得看：同框架里把 System One 换成 GPT-5.5，排序质量**基本持平**，但 System One 成本高出两个数量级（每 topic 约 $1.74–3.54 vs Jev $0.007–0.018）、全流程耗时是 Jev 的 4 倍以上；加深主动检查深度 K 并不单调提分。消融也显示「证据定位」本身加分有限、会增加 System Two token。

2. **[OpenLAIR/lev](https://github.com/OpenLAIR/lev)**（**10-14**；Apache-2.0；[项目页](https://openlair.github.io/lev/) · [HF Lev-2.6B](https://huggingface.co/songdj/Lev-2.6B) · [LevBench](https://huggingface.co/datasets/songdj/LevBench)）\
   「System 1.5」：把预训练循环（looped）语言模型改成类型化决策模型，共享 pointer head 在每个循环步都出选项概率，**同一 checkpoint 选深度换算力**。作者表（JevBench 231 道公开题）：Lev-2.6B 深度 1→4 为 63.2% → 76.2%，Lev-1.4B 58.0% → 68.0%，Lev-3B 69.3% → 72.7%。README 主动写明负结果：**Lev-2.6B 三个种子都没过 locked LevBench 的 G3 关**；提前停止的路由收益只是离线分析、依工作负载而定。论文目前在 alphaXiv，arXiv 待公告。

3. **[shibing624/train-jev](https://github.com/shibing624/train-jev)**（**10-14**；Apache-2.0；中英 README；[结果](https://github.com/shibing624/train-jev/blob/main/docs/results.md)）\
   中文开源作者 shibing624 的 System 1 决策模型训练框架：Qwen3.5 底座 + LoRA r16 + 24 槽位决策头，KL 蒸馏 Jev 1.13 完整分布，按题型拟温度，含 `/v1/systemone` 兼容服务。作者报 Qwen3.5-4B 上 3×H20 训 2.8 小时，分布内 KL **0.018**（对照 [autotrust/JEV-27B](https://huggingface.co/autotrust/JEV-27B) 0.017），只用文本训练、零样本看图决策 skill 0.632 → 0.697；也支持 Qwen3.8-27B。与上期 [decision-datagen](https://github.com/SunixLiu/decision-datagen)（造数据）互补：这里是训练 + 校准 + 部署一条龙。作者声明与 TypeSafe、autotrust 无关联。
