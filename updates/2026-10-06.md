## 竞品补记：阿里云百炼 decision-model-preview

**[百炼「决策模型 System One API」文档](https://help.aliyun.com/zh/model-studio/decision-model-api)**（文档约 **2026-09-26** 更新；国际站同文 [alibabacloud.com](https://www.alibabacloud.com/help/zh/model-studio/decision-model-api)）  
继 Cloudflare Clef 之后，国内云厂商也给出了 System One 形态的托管决策模型：`POST /compatible-mode/v1/systemone`，模型名 `decision-model-preview`，同样是 `choice` / `noul` / `score` 三类问题、一次前向返回概率与置信度。文档示例**直接用 TypeSafe 官方 SDK（`typesafe-sdk`）把 `base_url` 指到百炼网关**，即线协议与 Jev 同构；写明上下文上限 65,536 token、超长 state「会被拒绝或截断」，问题数不设上限但建议 ≤ 16。中文社区转述（[AI 热报转岚叔推文](https://airebao.com/item/36803)，约 09-27）称目前处于免费阶段——以控制台实际计费为准。窗口内已有中文接入：**[czyczy23/astrbot_plugin_jev](https://github.com/czyczy23/astrbot_plugin_jev)**（AGPL-3.0；约 **2026-10-05**）给 AstrBot 群聊插件的「要不要插话」加一层 50–70 ms 的决策复核，百炼 / OpenRouter `typesafe/jev-1.13` 一键切换，超时与异常一律回落原版逻辑。**提醒**：鉴于 [Clef 托管版的静默截断](../guides/gotchas.md)（第 30 条），长 state 场景同样先自测再上量。

## 值得一看的工具 / 开放模型（优先）

1. **[jiwidi/jiwo](https://github.com/jiwidi/jiwo)**（约 9★；代码 MIT、权重 Apache-2.0；约 **2026-10-05**）  
   面向低延迟场景的开放小决策模型 jiwo-0.8b / jiwo-4b（Qwen3.5 骨干），自带 `jiwo serve` 兼容 `/v1/systemone`，作者称单张 H100 中位约 50 ms。在社区跑分 [apolinario/decision-index](https://github.com/apolinario/decision-index)（本仓库此前未单列，可本地或一次 HF Job 复现 Jev 决策基准套件）上，作者自报 0.8b 得 28.00、4b 得 44.97，分别为 1B 以下与 3–6B 档榜首（尚未经榜单维护者核验）。难得的是 README 把**更高分的开放提交也列出来了**（如 Wald-Q4B 54.59，但中位 2,360 ms 超出榜单 1 s 限制）；训练数据以英文为主，其他语言未评测。

2. **[syn-ack-ai/synack-decide](https://github.com/syn-ack-ai/synack-decide)**（Apache-2.0；约 **2026-10-04**；权重 [SkyPanther/synack-decide-26b-a4b](https://huggingface.co/SkyPanther/synack-decide-26b-a4b)）  
   26B-A4B MoE 开放决策模型，给出 bf16、MLX 8bit、GGUF 三套权重；作者称 llama.cpp（2026-10 起）已有 `/v1/systemone`，并附可复现原始 prompt 的 GGUF 决策模板。CUDA bf16 约需 52 GB 显存。作者两条实用提示：多步组合题（如「第三大」）让代码做，模型只答判断；用有意义的选项键，`option_1` 这类泛名对模型不可见。相对 10-05 Clef / 09-28 Kev：本项是**更大号、可本机 llama.cpp 直跑**的开放替代。

3. **[amyivychoi/jev-browser-agent](https://github.com/amyivychoi/jev-browser-agent)**（MIT；约 **2026-10-05**；中文界面）  
   Browser Use 读页面、Jev 选下一步、Browser Harness 校验执行；置信度 < 0.95 或返回无效选项即交回聊天模型。作者做了**只换主决策模型**的配对对照：5 个浏览器任务上 Jev 与 Qwen3-32B 同为 4/5 成功，耗时 296 s 对 766 s、花费 $0.022 对 $0.045；但 Jev 臂 21 次决策里有 14 次走了兜底，样本也只有 5 题——更像「门控 + 兜底」架构的实测记录，而非 Jev 单独胜出。

4. **[deep-diver/jev-270m](https://github.com/deep-diver/jev-270m)**（约 **2026-10-05**；中英韩 notebook，前半段免费 CPU 可跑）  
   **负结果优先**的教学仓：直接读 Gemma 3 270M 的 Yes/No logits 在未见任务上 AUC 0.485（掷硬币），换 JSON 输出则 179 题全答 true；中层线性探针却有约 0.97——「模型知道，但说不出」。LoRA + pointer head（0.67% 参数）把同一未见任务拉到 0.821；训练更久反而掉到 0.724，按域内 dev 选 checkpoint 会选中迁移最差的那个。相对 10-05 LLM2Jev「不训练也能用」：本项给出**小模型上不训练就不行**的反例与边界。

5. **[uu889/laya-opencv](https://github.com/uu889/laya-opencv)**（约 **2026-10-05**；中文优先）  
   本地 Laya 一键安装包 + 网页工作台，2.0 起接 OpenCV：图像先分割测量，数字结论交硬规则，判定模型只做交叉核对，冲突或低置信度提示人工复核；内置水果采摘、病虫害、钢管与纺织质检方案，并能自动生成阈值两侧边界用例「实测模型对数字的判断力」。示例图为程序合成，无真实产线数据。

## 评测 / 负结果 / 安全（增量）

1. **[arXiv:2610.04985 · Hidden Risks of Jev](https://arxiv.org/abs/2610.04985)**（约 **2026-10-04** 提交；代码 [shihe98/Security_Privacy_Jev](https://github.com/shihe98/Security_Privacy_Jev)）  
   首个把 Jev 当「应用决策层」做系统安全 / 隐私研究：官方 API + 可控训练数据的本地 NanoJev，覆盖提示注入与对抗后缀操纵决策、训练数据投毒植入后门（供应链风险）、成员推断 / 属性推断等隐私攻击，以及检测与滥用（越狱、模型抽取）的两用性。结论是这些威胁在类型化输出下依然成立。相对 10-05 system-one-security（state 投毒 / 截断）：本项补上**后门与隐私推断**两块。

2. **[arXiv:2610.03935 · General Decision Models: Benchmarking and Insights Beyond Jev](https://arxiv.org/abs/2610.03935)**（约 **2026-10-02** 提交）  
   中英双语基准 JEVal：36 个数据集 11,257 题、25 种配置。结论分三层：证据就在输入里时决策模型很有竞争力，需要专业知识或真实不确定度时会**猜对答案却高估概率**；τ-bench 上更快的单步决策缩短时长但错误累积拉低成功率；社会模拟里个体预测接近大模型，聚合估计偏差更大。另放出 InnerJev-4B / 27B（推理自蒸馏到首 token），称 27B 在 JEVal 上与 Jev 持平、约 0.1 s 一问。

3. **[arXiv:2610.03387 · Benchmarking Candidate Coverage in Typed Decision Models](https://arxiv.org/abs/2610.03387)**（约 **2026-10-02** 提交）  
   专测「正确答案不在选项里」：TREC 5 选项时 Laya 能发现 97.2% 缺答案的情况但误拒 69.7% 正常题，Jev 正好相反（24.8% / 0.0%）；只用校准集定 none 阈值后分别变为 33.9%/3.7% 与 45.0%/1.8%。与 10-01 已收「拒答瓶颈」（2609.39496，算术场景）互补：本项是**通用分类上的配对协议**，结论是分类、排序与拒答要分开测。

4. **[arXiv:2610.03324 · To Jev or Not? … Hate-Speech Moderation](https://arxiv.org/abs/2610.03324)**（约 **2026-10-02** 提交）  
   HATEDECIDE：6 种决策模型配置 × 4 个仇恨言论数据集，对照专用审核、零样本、商用与监督基线。商用大模型仅在 1 个数据集上显著领先；给定义会改变最多 28% 的预测却不稳定提分，拆成多问只在 20% 的比较里显著有效；最佳托管决策模型距最佳商用模型 1.6 个 macro-F1，成本约低 97%。与 10-05「标签压过定义」同向：**写更长的定义不是免费午餐**。
