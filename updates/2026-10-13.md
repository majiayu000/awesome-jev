## 补记：社科七复现——速度有、批价成本优势没有（10-05）

**[arXiv:2610.06625 · JEV versus LLMs: Accuracy, Cost and Calibration on Seven Political Science Replications](https://arxiv.org/abs/2610.06625)**（Leiden；**2026-10-05** 首发，v2 **10-06** 修正作者元数据；HTML 全文）

- 规模：复现七项已发表政治科学标注 / 缩放任务（推文相关性与情感、GTD 袭击类型、开放题成对比较、宣言句打分、党派左右、V-Dem 指标回忆等），同一题面对照 JEV 1.13、GPT-6 Luna、开放权重 Qwen3.8-27B，并以各文人类编码为金标。
- 质量：与当代商业 / 开放 LLM 大致打平；对人类金标的准确率大多落在区间内，无「碾压」结论。
- 成本负结果：按作者实测 token，**相对 OpenAI Batch 价，JEV 在七项里六项更贵或持平**；相对 Luna Standard 即时价则六项更便宜。作者写明 JEV 把选项与题干都算进输入，每决策输入 token 约为 Luna 的 1.2–3.3×。
- 校准：单次询问时 JEV 概率相对 Luna 的 token 概率 ECE 更低（八项阅读任务均如此）；相对 Qwen3.8-27B **并非 consistently 更好**。Luna 在党派成对比较上 74% 的概率落在 <0.01 或 >0.99，JEV 约 18%。
- 速度：单请求中位约 0.09–0.27 s，对 Luna 约 0.75–1.04 s。作者结论：除非需要速度，JEV 在社科文本上「唯一明显优势」是选项概率好解析。

**对使用者的影响**：拿「比 LLM 便宜两个数量级」做社科批注预算时，先按 **Batch vs Standard** 和「每决策输入 token」各自算一遍；校准优势不要外推到所有开放模型。

## 独立评测与负结果（优先）

1. **[TypedBench · arXiv:2610.11392](https://arxiv.org/abs/2610.11392)**（DFKI / Imperial / Mila 等；**2026-10-08**，v2 **10-09**；[HTML](https://arxiv.org/html/2610.11392)）\
   面向 System One 接口的污染抗性基准：七个**策略可推导**的生成器 + 九套评测（校准相对有限样本 null ECE、改写稳健、选项数/长度、共问干扰、序数一致性、非对称代价下的决策价值等）。同题评测托管 Jev 1.13.0、Laya 英 / typed-decisions、Kev 0.8B/4B/9B。关键负结果：（a）**工单优先级**这种要套三条款规则的题，友好改写 alone 就把 Jev 准确率拉开约 **24 点**（中位 0.874，区间约 [0.708, 0.946]），敌意措辞再往下；（b）几乎所有模型×题型的 ECE 都高于 null，Jev **系统性偏低自信**（温度重拟合 <1）；（c）在「低估级比高估级更贵」的非对称代价下，对 Jev / Kev-9B 用完整概率做 Bayes 决策，**比直接取 argmax 更贵**（工单优先级例：Jev argmax 成本 1,080 → Bayes 2,300 / 万次）。作者明确：准确率要报改写区间、校准要按模型×原语×题型、概率质量要用部署代价评判。见 [踩坑 #35](../guides/gotchas.md)。

2. **[When Faster Decisions Do Not Make Better Agents · arXiv:2610.13092](https://arxiv.org/abs/2610.13092)**（南大 / TUM；**2026-10-09**；[HTML](https://arxiv.org/html/2610.13092)）\
   把 Jev 嵌进五类 agent（ALFWorld 上 ReAct / Reflexion；AndroidWorld 上 T3A / AutoDroid / FastAgent），每配置三轮、共 **4,500** 次任务执行。决策层：五家决策成本降约 66–78%、延迟降约 74–82%。任务层分化：ALFWorld 成功率接近基线（差约 1.5–1.7 pp）；AndroidWorld 上 T3A / FastAgent 掉约 **13 / 18 pp**。辅助推理与额外交互吃掉速度收益；失败恢复与过早宣称完成限制交付。**T3A 每次尝试更便宜，但按成功交付均摊成本反而升高**（68.70 → 73.97 mUSD / 成功，区间跨零）。代码匿名仓见文内链接。对「换上决策模型就整体更快更省」是直接负结果样本。

3. **[di37/decision-model-benchmarks](https://github.com/di37/decision-model-benchmarks)**（**10-12** 公开；逐条 `raw_results.jsonl` + 分析表均提交）\
   同一份原生 `/v1/systemone` 请求对照 **CLEF-Flash、Jev、Laya、CLM** 五套：Banking77 子集 154、Amazon ESCI 重排、MMLU 200、路由 90、BFCL v3 multiple 工具选择 200。作者表：Banking77 准确率 CLEF-Flash **93.5%** vs Jev **80.5%**（McNemar 精确 p≈1e-5）；MMLU / 路由 / BFCL 上 Jev 略高但 Holm 校正后与 CLEF-Flash **均不显著**；Laya / CLM 全面显著落后。中位延迟：Laya 约 8–20 ms、CLEF-Flash 约 69–323 ms、Jev 约 309–327 ms（含托管往返）。协议写明选项顺序固定、逐请求、结果可离线复算。注意：公开基准子集可能有污染风险，作者自己用的是原生同请求而非 TypedBench 式生成器。

## 其他值得一看（方法新、样本小）

- **[Suryals/llm-as-decision-model](https://github.com/Suryals/llm-as-decision-model)**（**10-12**；MIT；冻结 `results/*.jsonl`）：把本地 Qwen3.5-4B / Qwen3.8-27B **只读标签 token 的 logprobs**（从不生成文本），与 Jev 在 **310** 条合成运维告警上比三类决策。作者表（rubric 提示）：类别准确率 Jev 95% / 27B 96% / 4B 94%；优先级 76% / 79% / 68%*；是否叫人 79% / 85% / 79%；p50 约 264 ms vs 2.3 s vs 255–446 ms。\*4B 对「并列说明」放在列表前/后差 6 点。数据合成、优先级标签需人工复核——作者原文已写。适合当「小 LLM 当决策模型」方法笔记，不是生产上限。
