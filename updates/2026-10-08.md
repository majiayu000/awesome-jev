## 竞品：OpenAI 发布 Decisions API（公开测试，10-06）

**[OpenAI Decisions API](https://developers.openai.com/api/docs/guides/decisions)**（[社区公告](https://community.openai.com/t/decisions-api-is-now-available-in-public-beta/1403877)，**2026-10-06** 公开测试，官方称「未来几周 GA」）

- 专用端点 `POST /v1/decisions`，目前只有 `gpt-6-luna` 一个模型；接受文本与图片，三种题型 `predicate`（概率）/ `choice`（固定选项 + 置信度）/ `score`（按有序 `levels` 打分，返回各级概率加权后的值，可落在两级之间）。
- 官方称比经 Responses API 调同一模型快约 10 倍；定价只收输入 **$0.10 / 百万 token**，输出与缓存不收费（目前也没有输入缓存），另有区域与长上下文溢价。
- **字段和 Jev 不同**：证据放在 `input`（不是 `state`），是非题叫 `predicate`（不是 `noul`）；图片只能是内联 base64 data URL，不支持 http(s) 链接或 `file_id`。从 TypeSafe 迁过来不是改个 base URL 就行。
- 次日 **[Vercel AI Gateway](https://vercel.com/changelog/openai-decisions-api-now-available-on-ai-gateway)**（10-07）上线 OpenAI 兼容的 `/v1/decisions`：`openai/gpt-6-luna-decisions` 与生成用的 `openai/gpt-6-luna` 是两个不同 ID，计费也不同；同一端点把 `model` 换成 Jev、Liquid d1、Laya 也能调。需要 OpenAI SDK JS 7.30.0+ / Python 3.26.0+，AI SDK `experimental_decide` 需 `ai` 7.0.128+。

**第一份第三方对照**：[mateusfonsek/openai-decisions-vs-jev-vs-laya](https://github.com/mateusfonsek/openai-decisions-vs-jev-vs-laya)（10-07 跑，葡语场景，每家 450 例、0 失败）。agent 工具路由 8 选 1：Jev 88.0% / OpenAI 86.7% / Laya 30.7%（打乱选项取平均后 40.0%）；提示注入检测：OpenAI 精确率 100%、在「只是**讨论**注入」的难负例上 0 误报，Jev F1 96.6% 略高但难负例误报 4%；Jev 每千次便宜约 17–35%，两家去掉网络后都在约 55–90 ms。作者结论是两家质量「技术性打平」，零样本 Laya 在葡语上不可用。注意这是单人、单语种、150 例 / 场景的测试。

**对使用者的影响**：连同 [10-07 补记](2026-10-07.md) 的 Databricks、Inception、Perplexity，「System One」形态已有 OpenAI 入场，但各家的字段名、题型名、图片输入方式并不统一；写适配层时把字段映射放进代码，并在自己的标注集上各跑一遍再选。

## 独立评测与负结果（优先）

1. **[Ashutosh1910/jevpros](https://github.com/Ashutosh1910/jevpros)**（约 **10-07** 公开；[REPORT.md](https://github.com/Ashutosh1910/jevpros/blob/main/REPORT.md)）  
   经 OpenRouter 对 `jev-1.13-20260917` 做的 16 组压力实验，约 5.6 万次调用、总花费约 $3.42，**每次调用的请求与响应都入库**可复查。强项：数字比较 480/480、日期 159/160，255 选项纯查表 100%，约 25k token 无关文本下准确率仍 95–97%，64 并发下中位延迟稳定在约 400 ms。弱项：state 里**一行自称「策略管理员」的方括号文字**就翻转了 64% 的正确答案（准确率 93% → 33%）；例外规则嵌套到 10 层时掉到 56%（接近随机）；同一请求重发 5 次只有 4% 完全一致，8% 的是非题至少翻转一次；缺少关键事实时只有 33% 选「无法确定」。见 [踩坑 #32](../guides/gotchas.md)。

2. **[thddydgnl/jev-world-model](https://github.com/thddydgnl/jev-world-model)**（韩国忠北大学，投 KIIS 2026 秋季会议，稿件 10-08 完成）  
   把**冻结、未训练**的 Jev 当 TextWorld agent 的世界模型（每步问 7 道选择题预测动作结果），288 局：任务成功率 93.4%，与 oracle（92.7%）无法区分、高于失败记忆基线（79.5%）。LoRA 微调的 Qwen3-4B 在训练过的世界结构上 4 步推演更准（98.5% / 96.8% vs Jev 77.9%），但换到**没见过的结构**后跌到 71.5% / 66.5%，Jev 仍有 85.5%。另一个发现：零样本下「给选项问」明显好于「让模型写下一个状态」（83.0% vs 59.0%），差距主要来自 26% 生成结果无法解析。

3. **[DouglasSM747/SupplyRisk](https://github.com/DouglasSM747/SupplyRisk)**（预注册评测）  
   问 Jev「马瑙斯内格罗河水位 14 / 30 天内是否跌破 17.70 m」，对比气候学、趋势、相似年与训练了近百年数据的逻辑回归 / 梯度提升，2015–2024 十年保留集评分，分析计划在出结果前提交。14 天窗口 Jev Brier 0.042，显著好于气候学（0.078），与最佳训练模型（0.035）在不确定区间内打平；加入日期与年份没有提升 2023 / 2024 大旱的预测（作者用作「没在背答案」的检查）；2025–2026 一次性留出集里有 1 次误报。13,044 次调用共 $0.75。算术（距阈值、按当前速度几天到）放在代码里，遵循官方 jaggedness 建议。

4. **[TianJinWeiBoss520/social-risk-qwen-jev](https://github.com/TianJinWeiBoss520/social-risk-qwen-jev)**（中文，MIT；约 **10-07** 创建）  
   中文社交平台图文风险识别：Qwen3-VL 出结构化证据 JSON（发给 Jev 前去掉 Qwen 自己的标签），再由 Jev 按固定政策决策。170 条冻结测试集（厌女类）上，**第一名是 TF-IDF + 逻辑回归**（Macro-F1 90.36%）；纯 Jev 只读文本时有害召回仅 25.53%，加上 LoRA Qwen 图文证据后升到 68.09%（Macro-F1 63.04% → 79.74%）。作者把「测试后补做的对照」单独标注、不改冻结阈值，负结果写得很诚实；数据集与逐条预测不公开。
