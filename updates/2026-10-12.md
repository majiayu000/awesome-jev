## 竞品：Microsoft-Decision-1（10-09）

**[Microsoft · Introducing Microsoft-Decision-1](https://commandline.microsoft.com/microsoft-decision-1-model-foundry/)**（**2026-10-09**，Office of the CTO；[Foundry 文档](https://learn.microsoft.com/en-us/azure/foundry/foundry-models/how-to/use-foundry-models-microsoft-decision) · [OpenRouter 模型页](https://openrouter.ai/microsoft/microsoft-decision-1)）

- 是什么：从 **Qwen3.5-9B** 后训练的托管决策模型，闭源权重，只在 Microsoft Foundry（`GlobalStandard` / 部分区域 `DataZoneStandard`）与 OpenRouter 提供；厂商称后续会换 MAI / OpenAI 基座。文本输入，无解释输出。
- 接口：Foundry 路径 `<resource-endpoint>/providers/microsoft/v1/systemone`，请求体沿用 `state` + `questions`（`noul` / `choice` / `score`）；`model` 填**部署名**而非模型名，鉴权为 Entra ID token 或 `api-key` 头。官方文档自己写了「措辞和选项顺序会改变分数」「建议随机化选项顺序」。
- 价格：输入 **$0.042 / 百万 token**、输出免费，与 Jev 牌价完全一致。
- 厂商自报：36 项基准近 15 万题（对训练保持盲态）准确率最高；p50 比 GPT-6 Sol 快约 35×；8 类扰动平均翻转 1.3%，「选项改述 / 反转 / 打乱零翻转」。原文编辑注称发布后**补上了 Jev 的准确率与校准对比**。以上均为厂商数字。
- 第三方当天就有跟测（只作索引，口径各不相同）：[JevStation](https://jevstation.com/compare/jev-vs-microsoft-decision-1)（10-10，Banking77 / AG News 各约 100 条，准确率打平、Decision-1 校准更好，并发跑时被 Azure 限流一次）；[jahanzaib.ai](https://www.jahanzaib.ai/blog/microsoft-decision-1-foundry-jev)（迁移字段对照，指出厂商 85 ms 为同区测量，独立 Foundry 跑中位约 459 ms）。中文侧 [Datawhale · Jev Cookbook #39](https://datawhalechina.github.io/jev-cookbook/materials/39-microsoft-decision-1/) 已做中文转述，定位为「首个超大规模云厂商自营决策模型」，同样标注数字待独立复核。

**对使用者的影响**：同格式、同价格让「换供应商」看起来只是改 endpoint，但下面两份窗口内实测都说明阈值和顺序敏感性不跟着迁移，见 [踩坑 #34](../guides/gotchas.md)。

## 独立评测与负结果（优先）

1. **[kartikanand73/decision-api-benchmark](https://github.com/kartikanand73/decision-api-benchmark)**（**10-10** 公开；MIT；两次完整运行的逐条 `calls.jsonl` 均在仓库）\
   银行提现路由（approve / step-up / manual review + 账户盗用概率），500 条合成案例 × **6 种选项顺序** + 重复，每轮 9,165 次调用，三家全部经 OpenRouter 发**逐字节相同**的请求。Route macro-F1：Jev **89.2%**、Microsoft-Decision-1 **87.6%**（两者区间重叠，统计上打平）、OpenAI Decisions **71.4%**。OpenAI 在 6 种顺序下 179/500 例改判、macro-F1 在 60.6–86.6% 间摆动；Jev 改判 41–42 例，Decision-1 12–14 例（厂商「零翻转」实测为 2.4–2.8%）。关键负结果：同一套为 Jev 调好的阈值下，Decision-1 每轮多送约 **50** 个正常单去人工复核（Jev 1–2）。Decision-1 最便宜主要因为分词器（同请求 423 vs Jev 773 token）。复现性：OpenAI 两轮 498/500 概率完全一致，Jev 有 24/500 例两轮改判。作者自己标注：合成数据、一晚两轮、单一路由。

2. **[jakeashcraft/jev-style](https://github.com/jakeashcraft/jev-style)**（**10-11**；C# 客户端 + 基准）\
   复用作者先前的 975 条工业 CIP 布尔表达式数据（对照一份模拟 PLC 快照判真假），经 OpenRouter 跑 Jev 1.13 与 Microsoft-Decision-1，另跑本地 [Jev-Style-Qwen3.5-2B GGUF](https://huggingface.co/chaoliangUNSW/Jev-Style-Qwen3.5-2B-Decision-GGUF)。Jev 单条请求 **99.9%**、Decision-1 **99.3–99.5%**；每请求塞 50 条表达式时两者都降到约 99%。本地 2B 只有约 **79%**。同一数据集上 Decision-1 每遍约 $0.0054、Jev 约 $0.0156（单条模式）。说明「开放 2B 仿 Jev」与托管模型在规则型判断上差距仍很大。

3. **[pirrer/taiwan-sovereignty-decision-models](https://github.com/pirrer/taiwan-sovereignty-decision-models)**（**10-09 00:21 Asia/Shanghai** 公开，上期未收；约 10★；代码 MIT、数据与论文 CC BY 4.0；[繁中摘要](https://github.com/pirrer/taiwan-sovereignty-decision-models/blob/main/README_zh.md)）\
   与中文用户直接相关的**字形敏感性**测试：28 句台湾相关陈述，繁中 / 简中（OpenCC 逐字转换，语义相同）/ 英文，3 种问法 × 3 种人设 × 3 次，共 18,225 次调用，对象为 OpenAI Decisions、Jev 1.13.0、Clef 27B、Clef-flash，Claude Haiku 5.5 作对照。四个决策模型在简体下都显著偏移（繁−简差：Jev 0.27、Clef 0.47，区间均不含 0），对照 LLM 只动 0.05；其他国家的中性事实对照没有字形差异。Clef 单句「不受 PRC 管辖」繁 0.95 → 简 0.06。另：Decisions / Clef / Clef-flash 三次重复概率完全一致。原始结果与分析脚本全部公开。本仓库只记录方法与数字，不评价议题本身；**做中文审核 / 分类的使用者应把繁简分开评测**。

## 补记：10-07 / 10-08 发布、前两期漏收的三份对照

- **[Arize · Decision model benchmark](https://arize.com/blog/decision-model-benchmark/)**（**10-08 00:37 Asia/Shanghai**，Jim Bennett）：八个决策模型（Jev 1.13、Liquid d1、OpenAI Decisions、Clef 27B、Kev 9B、Jeeves 9B、Strands Decider 2B、Laya）在 RAGTruth 2,675 行、Phoenix 13 套评测 655 例、52 个路由决策上做淘汰赛；头部几家准确率大多落在置信区间内打平。最有用的是「The twist」：把问题从「每条陈述都有依据吗」反写为「是否含无依据陈述」，只有 Jev（0.93→0.93）、Clef 27B、OpenAI 稳住，**Liquid d1 从 0.92 掉到 0.17**、Jeeves 0.25、Strands 0.26。与 09-21 收录的 Arize「Jev 当 judge」是不同文章。
- **[StackToHeap · OpenAI Decisions API: How Does Jev's Big-Lab Competitor Fare?](https://stacktoheap.com/blog/2026/10/08/jev-the-decisions-strike-back/)**（**10-08**）：沿用作者 BANKING77 样本，只给定义时 Jev 81.17% vs Decisions 78.96%；每个意图给两条示例后 85.32% vs 84.16%。Decisions 平均延迟更低（194 vs 520 ms），但成本约 $0.30 vs $0.18，且有少量拒答需要应用层处理。结论：给示例的收益大于换模型。
- **[BTInsights · Jev vs OpenAI Decisions 问卷开放题编码](https://btinsights.ai/blog/jev-vs-openai-decisions-api-coding-accuracy/)**（**10-08**）：2,617 条人工编码的真实问卷回答，逐码问 yes/no。默认 0.5 阈值下两者打平（F1 72.2 vs 72.9），都多打约三分之一的码；按题调阈值后 Decisions 77.1、Jev 75.4，但赢家随题目翻转（宠物题 Decisions、急诊题 Jev）。Decisions 成本约 7×。作者自家做问卷编码产品，结论「专用工具更准」需带着利益相关读。

## 其他值得一看（方法新、样本小）

- **[kyle-pena-nlp/beelinebench](https://github.com/kyle-pena-nlp/beelinebench)**（10-09；Apache-2.0；PyPI + Zenodo DOI）：用决策模型给 best-first 搜索的前沿状态排序，看多步问题（8 数码、Blocksworld、Countdown、Wikispeedia 等 7 个域）能否「直奔」最短路径。v1.0.0：Mercury Decide / pplx-decider 0.28、Jev 0.26、Liquid d1 0.22、OpenAI Decisions 0.19，经典启发式 0.25；作者明说 A* 仍是正解，这只是测规划能力的尺子。
- **[jrterven/jev-vs-rag](https://github.com/jrterven/jev-vs-rag)**（10-10；「Scan or Index?」论文配套）：长文档 RAG 中把 Jev / Decisions / Clef 当重排器或全文扫描器。Hybrid + Jev 教材证据覆盖最高（94.1%），但自动答案准确率反而是 Hybrid + Decisions 更高（0.892 vs 0.864）；同一文档复用到第 6 次查询起，稠密检索就比 Hybrid + Jev 便宜。负结论：更多证据不一定换来更好的答案分。
- **[clouatre-labs/judge-enumeration-exhibit](https://github.com/clouatre-labs/judge-enumeration-exhibit)**（10-11；预注册）：用 `jev-1.13.0` 在小规模线性规划候选菜单里挑最优解，120 题 × 2 遍全部答对——作者把它定性为**题目太容易导致的天花板**，不是能力证明。可作为「预注册 + 封存分析」的写法参考。
