# Jev 社区观察 · 2026-11-02

覆盖窗口：约 **2026-10-30 10:00 Asia/Shanghai**（上期 [2026-10-30](2026-10-30.md) 定稿）之后至本稿（约 **2026-11-02 10:00 Asia/Shanghai**，含周末），另补记 10-26 至 10-30 挂出、此前各期都没收的几篇 arXiv 论文。本期主线：**规则怎么写、分数有没有用**——一份 130 万次请求的编码 agent 策略门研究显示，同一个 Jev 只是把规则从「一句定义」换成「带边界和正反例的规则」，漏拦率就从约 11% 降到约 2%、误拦也降了约三分之二；一份 16 天、5,300 次调用的多 agent 流水线复盘标题就叫「准确但没用」；多语种重排、土耳其招聘广告、仓储图像几份对照把 Jev 的强项和短板都量了出来。仓库星标普遍为 0–1，按方法与可核对材料收录；所有数字均为原作者自报，本仓库未独立复现。

## 独立评测与负结果（优先）

1. **[agentapprove/decision-policy-rules](https://github.com/agentapprove/decision-policy-rules)**（**11-01 建仓**；论文 *Decision Models as Policy Gates for Coding Agents: Explicit Policy Boundaries Improve Detection and Reduce False Alarms* 的配套数据，arXiv 待挂）\
   编码 agent 工具调用的「放行门」研究：2,643 个合成工具调用、106 个场景族（1,535 开发集 / 1,108 封存测试集）、28 个规则模板，外加 320 例确认集，约 130 万次请求，对比十几个决策模型。同一模型、同一批动作，只换规则文本（[holdout_ci.csv](https://github.com/agentapprove/decision-policy-rules/blob/main/results/paper-data/holdout_ci.csv)，封存测试集）：
   - **Jev 1.14**：产品原版「只有定义」的规则——召回 89.38%、误报率 2.90%、干净动作被打断 32.54%；换成 Opus 写的「带明确边界 + 正反例」规则——**召回 98.20%、误报率 0.83%、打断 4.76%**。Jev 1.13 同向：85.28 / 2.52 → 97.39 / 0.82。
   - 其他模型也一样受益：OpenAI Decisions 召回 87.70 → 98.51，Liquid d1-ultra 87.83 → 98.14；但 ScaleDown Classify-1 换规则后反而变差。
   - 单条规则的极端例子：「给特定的人发 Slack 私信」这条，Jev 1.14 用产品原版规则召回只有 8.16%，换写法后 97.96%。
   - 成本：Jev 约 $0.33–0.46 / 千次，p50 延迟 102–120 ms。
   - [人工审计 Jev 1.14 剩下的 29 个漏拦](https://github.com/agentapprove/decision-policy-rules/blob/main/rounds/r4/AUDIT-JEV-1-14-MISSES.md)：13 个是动作文本里写着却没看到，10 个是动作里根本没有判定所需信息（比如推送的仓库是不是项目自己的 remote）；把项目的 git remote 等可信上下文一起给它后，这类题 Jev 1.14 从 16/26 升到 23/26。见 [踩坑 #53](../guides/gotchas.md)，与 [踩坑 #47](../guides/gotchas.md) 互补。

2. **[sash-ua/jev-experiments](https://github.com/sash-ua/jev-experiments)**（**10-30 建仓**；配套文章 *Accurate and Useless: What 5,300 Calls to a Small Judge Model Taught Us*）\
   把 Jev 1.13 塞进一条多 agent 的 Claude Code 构建流水线，10 月里跑了 16 天：5 次构建 4,222 次调用 + 1,092 次离线调用，`recompute.mjs` 可复算 103 项检查。**结论是负的，最后把 Jev 撤掉了**：
   - 高准确率主要来自「跟着多数答案走」：96% 的文件本来就和任务无关。
   - 文件筛选「是否与任务相关」AUC 只有 0.54；「可能需要改」AUC 0.955，但只有 6 个正例，而且全部低于 0.7 阈值，等于一个都没拦下。
   - 范围必要性判断 172/240（72%）不给结论；接口契约一致性 191/191 全答「一致」；测试强度 AUC 0.23（方向反了）。
   - 唯一亮点：判断「这段代码和这个结论无关」AUC 0.97。
   - 下游 agent 几乎不照着 Jev 的回答行动（各环节 0 / 2 / 39 / 10 次），省下多少 token 也从未被测过。启示：先报多数类基线和 AUC，再看准确率；没有改变 agent 行为的判断，再准也没用（参见 [踩坑 #45](../guides/gotchas.md)）。

3. **[vkehfdl1/jev-reranker](https://github.com/vkehfdl1/jev-reranker)**（**11-01 建仓**，运行记录 10-02 至 10-23）\
   Jev 当重排器的多语种对照：
   - MIRACL（18 种语言 × 252 查询，K=100）nDCG@10：Jev 1.14 批量逐条打分 0.7552、整表排序 0.7463；voyage rerank-2.5 0.7989、nemotron（免费）0.8121，BM25 0.4427——**Jev 在专用重排器后面**。当预筛用时，P(yes) ≥ 0.5 平均每查询留 15.1 篇、保住 85% 正例。
   - JQaRA（日语 1,667 查询）反过来：**Jev 1.14 逐条打分 0.8849，高于 cohere rerank-4-pro 0.8191 和 gpt-6-luna 逐条 0.8077**；但 Jev 整表排序只有 0.6992，比逐条低近 0.19。约 $1.14 / 千查询，0.49 s。
   - 启示：同一个模型，「每篇单独问相关吗」与「把整列交给它排」差距可以很大，选法要在自己的数据上两种都测（与 [踩坑 #50](../guides/gotchas.md) 同属重排细节）。

4. **[kubrakrcn/kariyer-decision-bench](https://github.com/kubrakrcn/kariyer-decision-bench)**（**10-30 建仓**；土耳其 Kariyer.net 研发）\
   600 条真实土耳其语招聘广告 × 7 个问题 = 4,200 个决策：Jev 1.13.0 准确率 **71.5%**、资历等级 MAE 0.40，高于自家 4B 模型（cisimcik-4b 提示版 65.7%，tau-4b 64.6%）；**但校准更差**：ECE 0.156 vs tau-4b 0.093。tau-4b 在自己的训练分布上 95.7%，换成真实广告掉到 64.6%。人工复看 40 个错例：17 个是标注错、16 个是分类体系本身模糊、只有 7 个是真错。给选项加描述：tau +2.2 点，Jev 只 +0.2 且校准变差。单次运行、无置信区间。

5. **[RajaRuling/bin-replenish-lab](https://github.com/RajaRuling/bin-replenish-lab)** 与 **[RajaRuling/parcel-lens](https://github.com/RajaRuling/parcel-lens)**（**10-30 建仓**，均预注册，`jev-1.14.0` 图像输入）
   - 仓储货格：150 张真实 Amazon Bin Image 照片，判断「空不空」Jev 93%（自训小模型 99%），四档库存水位只有 **58%**（自训 78%，宏 F1 54 vs 75），45 个「中等」里有 26 个被判成「低」；每张约 0.14 s。
   - 包裹破损：150 张合成图，AUC 76 vs 自训 96，**破损召回约 17%**（自训约 92%），没有误报；画框与真值重叠 ≥50% 的占 59%。75 张完好包裹它也全部给出了框，要先单独问「有没有」；小于 336 px 的图会被拒，需要先放大。

6. **[TetraspaceW/decision-model-evals](https://github.com/TetraspaceW/decision-model-evals)**（**10-30 建仓**）\
   100 道已结算的 Metaculus 二元预测题（64 道结果为否），经 OpenRouter decisions / chat 接口问各模型概率。仓库只放了逐题结果，没有汇总表；按其 `results/*.jsonl` **本仓库自行计算**的平均对数得分（越接近 0 越好，概率截断到 0.001–0.999）：Claude Opus 5.5 −0.177、GPT-6 Astra −0.268、Liquid d1-ultra −0.473、Nace Drex Max −0.486、**Jev 1.14 −0.563、Jev 1.13 −0.568**、MS-Decision-1 −0.662，恒报 50% 为 −0.693、恒报 36% 约 −0.653，gpt-6-luna −2.057（过度自信）。题目已结算，主要考的是模型知道多少旧闻，不是预测能力；100 题、无区间，只作参考。

## 论文补记（10-26 至 10-30 挂出，此前未收）

- **[arXiv:2610.38895 · FlipJev](https://arxiv.org/abs/2610.38895)**（10-28）：黑盒查询攻击，不用攻击者 LLM。常见提示注入在 10,240 组配对测试里一个正确答案都没改动；但几分钟就能搜出短后缀翻转高置信答案，每个数据集一条后缀能翻转 43% 未见文档，**跨任务迁移时翻转 90–100%**。放进安全敏感流程前要做自适应攻击测试。
- **[arXiv:2610.39747 · When the Top Answer Decides: Gender Bias in Decision Models](https://arxiv.org/abs/2610.39747)**（10-29）：Jev 与 5 个开放决策模型，6 个里 5 个对女性给出更有利的答案（对数几率 +0.05 至 +0.10），换性别改动 1–3.5% 的首选答案；厂商推荐的置信度门槛去掉了不少有偏答案，却让 BBQ 模糊题里留下来的答案刻板比例更高。与上期 [踩坑 #52](../guides/gotchas.md) 同一方向。
- **[arXiv:2610.36311 · Confidence Is Not a Promise](https://arxiv.org/abs/2610.36311)**（10-26）：开放 Laya 五个检查点对 Jev 1.13。按点估计挑阈值，190 次评估里 147 次兑现不了承诺的准确率，Learn then Test 全部兑现；**在英文上校准的 Jev，95% 的承诺只在 51 个语种里的 8 个成立**；普通打字噪声也会打破干净文本上校准的承诺。
- **[arXiv:2610.40318 · 风湿科考试题与诊断病例](https://arxiv.org/abs/2610.40318)**（10-29）：西班牙专科考试题 Jev 1.13 约 92–93%（GPT-6 Sol 99.4%），概率 ≥0.90 的答案 98.5% 正确；换成 5–18 个候选诊断的病例题，Jev 只有 50.0% 且过度自信，≥0.90 的答案只有 84.6% 正确。
- **[arXiv:2610.38448 · 决策模型 vs 生成式 LLM 做 MedQA](https://arxiv.org/abs/2610.38448)**（10-28）：13 个决策模型 67.71–89.08%，15 个生成式配置 78.32–96.86%；决策模型概率 ≥0.90 的答案错误率 1.71–12.77% 不等，三次运行答案一致率 92.30–100%。
- **[arXiv:2610.38623 · Cross-Primitive Consistency in Jev](https://arxiv.org/abs/2610.38623)**（10-28）：同一语义换成是非题 / 选择题问，三个规模的 Jev 在四个维度上都有不一致；不一致本身能以 ROC-AUC 0.91 预测答错。代码见 [67L1/PrimaCons-CRPR](https://github.com/67L1/PrimaCons-CRPR)。
