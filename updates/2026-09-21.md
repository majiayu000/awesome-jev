# Jev 社区观察 · 2026-09-21

一次性深挖（约近 7 日公开信号），对照已有 [W38](2026-W38.md)、[09-20](2026-09-20.md) 与 catalog，只记**可核对且用途清楚**的新条目。性能数字均来自原作者或实验方，本仓库未独立复现。

## 值得一看的工具（优先）

1. **[Kiln-AI/jev_jsonschema](https://github.com/Kiln-AI/jev_jsonschema)**（约 7★，PyPI `jev_jsonschema`）  
   把 JSON Schema 属性映射为 Choice / Score / Noul，再把答案解码回可校验 JSON。转换层与 HTTP 客户端可拆开用。明确拒绝自由字符串、`array`/`object`、`anyOf`、超宽整数区间等无法映射的 schema。适合「旧结构化输出管线想接 Jev」的桥。

2. **[utk2103/jev-studio](https://github.com/utk2103/jev-studio)**（约 13★，PyPI `jev-studio`）  
   一站式 CLI（`verify` / `screen` / `classify` / `route` / `compact` / `batch` 等）+ stdio MCP。支持 TypeSafe / OpenRouter / Cloudflare 凭证。作者说明 CLI 是对 [`Nasrallah-AL/jev-cli`](https://github.com/Nasrallah-AL/jev-cli) 的 Python 移植。

3. **[nexibeo/jev-cookbook](https://github.com/nexibeo/jev-cookbook)**（约 10★）  
   15 个可跑配方（分流、去重、PII、检索重排、日志分流、浏览器步骤等），带小样本标注结果与 `results/`。经 **OpenRouter Decisions API**（`/api/alpha/decisions`，模型 id 需 `~typesafe/jev-latest` 前缀波浪号）。数据集小，作者自陈不是正式 benchmark。

4. **[nozomi-koborinai/jev-spec](https://github.com/nozomi-koborinai/jev-spec)**（约 4★，2026-09-20 起活跃）  
   规格驱动的语义校验：用 Jev 对照 AI 代码/规格做验证，方向偏「规范 ↔ 实现」门禁，而非又一个 MCP 壳。

5. **[AkashPriyadarshii/jev-git](https://github.com/AkashPriyadarshii/jev-git)**（约 2★，crates.io `git-jev`）  
   Rust 静态二进制：`git jev install|check`，对 staged diff 做密钥 / 注入 / 破坏性命令等 Noul 门禁。星少但用途单一清晰；作者自称约 80ms p50，未经验证。

6. **[Dicklesworthstone/skillranker](https://github.com/Dicklesworthstone/skillranker)**（约 105★，近日持续推送）  
   Rust CLI `sr`：用 Jev 对当前会话可见 skill 做两段 Choice（含 none），大库先本地 Quill 预筛。catalog 原始采集里已有条目，本轮作为**高星、可执行的 agent-tool**再提示一次；需自备 TypeSafe key，默认不联网。

### 新工具（优先）

1. **[kylemclaren/jevql](https://github.com/kylemclaren/jevql)**（约 10★）
   面向**原版 Postgres**的语义 SQL：在 CLI / MCP / Go·TS·Python SDK 里写 `WHERE jev(...)`、`jev_prob` / `jev_choice` / `jev_score`，服务端只跑普通 SQL，客户端批量调 Jev 并本地 SQLite 缓存。不是扩展、不改 wire 协议。作者强调：先放便宜 SQL 谓词，再用 `--explain` 估行数与费用；行内容会发往 TypeSafe。

2. **[carldaws/hunch](https://github.com/carldaws/hunch)**（约 13★，gem `hunch`）
   Ruby「概率控制流」：`Hunch.likely?` / `pick` / `rate` / `decide` 一批多问，可 stub 后端做单测；README 含 Rails 校验、入站邮件分流、错误分级与重试示例。TypeSafe 或 OpenRouter Decisions。

3. **[kyu1204/jgrep](https://github.com/kyu1204/jgrep)**（约 10★，npm `jevgrep`）
   语义 grep：按行为描述搜代码或 `--diff` hunk，也可对 CSV/JSONL 行批量提问。块在隔离状态下判定（跨文件流问不中）；适合 CI「用英语写规则扫 diff」。

4. **[abhixhek/jevcal](https://github.com/abhixhek/jevcal)**（约 10★）
   在**自有标注数据**上量测阈值、写出 `decisions.lock.json`、CI `jevcal check` 防漂移；可选 LLM teacher 补标与改写。README 刻意不公布 Jev 榜单数字（称受客户协议限制）。作者写明于 2026-09-18 对 `jev-1.13.0` 做过端到端核对。

5. **[doronp/jevc](https://github.com/doronp/jevc)**（约 4★，npm `jev-compiler`）
   星少但方法独特：把 `CLAUDE.md` / `AGENTS.md` 等策略散文 **编译** 成窄证据题 + 代码 reducer，并可 `emit-policy` 给既有钩子；强调「勿问塌缩 verdict、证据题与判定分家」。58 条离线 fixture；`--live` 才需 key。与 Kiln JSON Schema 桥不同：入口是仓库里已有规则文件。

### 1. 评测 / 负结果 / phishing / 诚实 caveat

1. **[Aman Kumar · Testing Jev…](https://amankumar.ai/blogs/jev-measured)**（约 2026-09-18）+ 公开半部仓库 [`onlyoneaman/jev-eval`](https://github.com/onlyoneaman/jev-eval)
   ~16k 次调用：短文本分类上与 gpt-5.4-mini / gpt-5.6-luna 持平或略优（Enron/SST-2/AG News），**Banking77（77 类）双方 LLM 更高**；生产页门禁适合做「两端过滤」，整页/模糊标签任务明显变差。结论写成一句话：**filter，不是 replacement**。钓鱼单题 62.6% vs Haiku 81.3% 与窄信号+逻辑回归可达 ~95% 的对比亦收录于此文。非本仓库复现。

2. **[JevBench · phishing vs Haiku 4.5](https://jevbench.xyz/benchmarks/phishing-email-detection)**（PhishNChips v5.2，n=2000，`jev-1.13.0`，标注独立可复现）
   公开数字：Jev 准确率 62.6% [60.5%, 64.7%]、钓鱼召回 43.2%、FPR 18.0%、AUROC 0.689、ECE 0.154；Haiku 4.5 为 81.3% / 76.4% / 13.8% / 0.837 / 0.097。文内自述约 12× 更便宜但「漏掉大半钓鱼」。artifact 与 [`anisselbd/jev-phishing-bench`](https://github.com/anisselbd/jev-phishing-bench) 同系；首页与 gotcha #9 已链仓库，本轮补**带置信区间与「不证明什么」清单**的展示站。

3. **[Arize · Can decision models replace LLM judges?](https://arize.com/blog/typesafe-jev-llm-judge/)**（Laurie Voss，2026-09）
   评测/可观测厂商视角：强调厂商 board 多对照**模型参考概率**而非人工金标；丢解释文本是主要损失；建议「全量走决策模型、失败/中间带再抽样 LLM judge」。属架构评论，非新榜单复现。

4. **旁注（诚实但星极少，不升格优先）**
   [`yodablocks/jev-orderby-bench`](https://github.com/yodablocks/jev-orderby-bench)（竞品清单已收）：预注册门控下，`ORDER BY` Jev 概率在 20 Newsgroups 过关、在 Amazon ESCI 六条里挂四条；批形状会改数字。0★，方法清楚，作负结果索引即可。

### 2. 路由 / 压缩 / MCP / agent 门禁（方法独特优先）

1. **[shitianfang/jev-use](https://github.com/shitianfang/jev-use)**（约 11★）
   Claude Code / Codex / pi 插件：无文本输出的步骤交给 Jev；`escalate: true` 类型化回退（writing / oversized / unsure / unreachable…）；PreToolUse gate 只 deny/ask；自带可重跑 `bench/` 与**含 Jev 更差的跑次**。压缩 demo 与 shell gate 同仓。竞品清单近期条目；优于又一个裸 MCP 壳。

2. **[shiftynick/jev-axi](https://github.com/shiftynick/jev-axi)**（约 17★，npm `jev-axi`）
   Agent 友好 CLI：本地规则先放行例行命令，灰区一次 Jev 多 hazard（destructive / remote_code / 注入筛网页等）；可装 PreToolUse。自述 agent 用它后「读更少文件、费用差不多」——作者定位为判断层而非替代读代码。catalog 已有采集，本轮作**高星门禁**再提示。

3. **[Nyarlathoteppppp/pi-jev-context](https://github.com/Nyarlathoteppppp/pi-jev-context)**（约 5★）
   写时裁剪长工具输出、不碰已进上下文的缓存前缀；`context_recall` 可原样取回。公开 [FINDINGS](https://github.com/Nyarlathoteppppp/pi-jev-context/blob/main/docs/FINDINGS.md)：Jev **不会**保护「现在无关、以后要用」的事实；真实会话回放里「只留 Jev 选中」约 **17%** 裁剪藏起了后来用到的事实——现策略改为仅藏自信无用块 + 失败行等硬保留。默认 shadow。竞品清单独有、负结果可核对。

4. **[luantak/is-malicious](https://github.com/luantak/is-malicious)**（约 18★）
   扫源码/配置/CI，把可疑行为标到文件与行；README 写明干净报告≠安全、内容发往 TypeSafe。竞品清单 agent 工具区高星项。

### 3. 浏览器 / computer-use / ultrafast 周边

1. **[chy4pro/jev-for-chrome](https://github.com/chy4pro/jev-for-chrome)**（约 12★；同作者 [`JevBrowserExt`](https://github.com/chy4pro/JevBrowserExt) 描述同系）
