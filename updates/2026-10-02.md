## 值得一看的工具（优先）

1. **[mertkayacs/jevalt](https://github.com/mertkayacs/jevalt)**（约 4★；Apache-2.0；约 **2026-10-01**）  
   开源三语 4B 决策模型：**Deem-4B**（英）、**Karar-4B**（土）、**Wähler-4B**（德），线协议兼容 `POST /v1/systemone`，现有 Jev 客户端可直接指到本机；Q4_K_M 约 **3 GB RAM** 可在 CPU 跑。作者在自有语言 hold-out 上报配对 bootstrap 约 **+4.4 / +5.1 / +11.5** 准确率点；域外（TurkishMMLU、typed-decisions、JevBench-hard）多无显著增益。相对 09-28 Kev / 09-24 JevK5 / 09-30 Jeff：本项是**可装可跑的多语小模型 + 完整 bench 产物**，不是又一个空壳 chat 包装。演示：[HF Space](https://huggingface.co/spaces/mertkayacs/JevAlt)；数字见 [jevalt-bench](https://huggingface.co/datasets/mertkayacs/jevalt-bench)。

2. **[gulbaki/jev-llm-guard](https://github.com/gulbaki/jev-llm-guard)**（约 9★；MIT；约 **2026-09-30**）  
   用托管 Jev 做**上下文相关**的 LLM 护栏：输入按 user / retrieved / tool / model 分源，返回本地 `allow` / `review` / `block` 与十项 [OWASP LLM Top 10 2026](https://genai.owasp.org/resource/owasp-genai-llm-top-10-2026/) 风险信号；作者明确分数是**文本风险信号**而非校准漏洞概率，缺上下文则 `needs_context`。带土耳其/英语交互 demo 与可部署的限流策略。相对 09-30 Decision Hijacking（攻击决策接口本身）与既有 phishing-bench：本项是**可安装的护栏产品形态**，不是攻击论文。Demo：[jev-llm-guard.vercel.app](https://jev-llm-guard.vercel.app)。

## 评测 / 负结果 / 综述（增量）

1. **[arXiv:2609.33209 · Beyond Calibration…](https://arxiv.org/abs/2609.33209)**（东北大学；提交约 **2026-09-27**；此前 dig 未收录；代码 [bro789/typed-decision-coherence](https://github.com/bro789/typed-decision-coherence)）  
   不用金标，用逻辑相关题组测**概率公理一致性**：ChaosNLI + PubMedQA 共 160 题、480 组否定对。Jev 否定互补 MAD 约 **0.064**（Qwen3.8-27B first-token 约 **0.293**、verbalized 约 **0.122**），差距在置信匹配、去双否定、重复平均后仍在；但 Jev **仍不连贯**——单标签过认（三项 \(s_k\) 平均和约 **1.14**）、yes/no 与 Choice 同标签差约 **0.09**，违规约为重复噪声底的五倍。实务含义：不同题型概率勿混进同一决策规则；三分区上不要把三个独立 Noul 当分布。相对官方 jaggedness「Noul≠Choice」与 gotcha #14：本项给出**可复现的 identity battery 与噪声底**。

2. **[arXiv:2609.36965 · Chinese-Jev…](https://arxiv.org/abs/2609.36965)**（复旦 / NUS 等；约 **2026-09-29**；项目 [gulucaptain/Chinese-Jev](https://github.com/gulucaptain/Chinese-Jev) / [项目页](https://gulucaptain.github.io/Chinese-Jev/)）  
   面向中文的 System One：统一把异构标注转成候选概率目标，先在约 **1000 万**通用中文决策上训 General（~322M encoder），再独立微调医/法/财。自建 **CJ-Bench**（约 30.8 万 hold-out）：General ACC 约 **69.20%**、ECE 约 **3.78%**（作者对照托管 Jev 约 68.35% / 11.45%）；医学 specialist 相对 Jev 约 **+4.0%** 相对准确率，三域平均约达 Jev 的 **92%**，本地中位延迟约 **14–15 ms**/例（H200 batch=1；对照托管 API 含网络）。INT8 浏览器原型在测试机 iPhone 15 Pro 上约 **1 s**/决策。相对官方「英文为主、CJK 需自测」与既有 MacJev/足球小模型：本项是**可核中文评测协议 + 通用/专科流水线**，不是科普转载。

3. **[arXiv:2609.33401 · Evaluating System One Models for Agent Security Decisions…](https://arxiv.org/abs/2609.33401)**（TraceStone / NTU；约 **2026-09-27**；产物 [yxsec/system-one-security-eval](https://github.com/yxsec/system-one-security-eval)）  
   在 WAInjectBench / R-Judge / AgentHarm 上对照 Jev、Laya、Decider、Nimble 与专用检测器及 LLM judge：总体排名可掩盖**攻击子群**失败（如 Jev 对无显式指令的注入亚群高置信漏检）；严格漏检预算下自动放行很少，独立 allow/block 阈值主要靠**多挡**抬覆盖；确认集过关不保证测试集仍满足预算；二审 judge 可纠部分错，但也会共享高置信漏检并引入新误报。相对 09-30 Decision Hijacking（操纵 Choice 概率）：本项是 **allow/block/review 自动化预算**下的系统对比。

4. **[arXiv:2610.00346 · Benchmarking System One… for automated decision gates](https://arxiv.org/abs/2610.00346)**（约 **2026-09-29**）  
   同一 harness 上比较六族共八个决策检查点（含托管 Jev）与监督/零样本分类器及生成对照：有任务标签时小分类器在 intent 上常最强；无标签时多数决策模型超过零样本 entailment；存储温度在选项变多时抬 ECE；5% 域内风险阈值仍可让 Jev 接受约 **0.310** 域外请求；yes/no 对调可致 Jev 约 **50.5**/百题翻转。给出**条件依赖**的门控设计规则（何时用训练分类器、何时用决策模型、何时做 intent→Jev 级联）。相对 10-01 TDM checklist：本项是**门控场景对照实验**，不是文献审计。
