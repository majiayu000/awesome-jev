## 独立评测与负结果（优先）

1. **[senko/classification-demo](https://github.com/senko/classification-demo)**（**10-27**；演讲配套「Classification without fine-tuning: Jev vs. BERT vs. LLMs」；[完整报告](https://github.com/senko/classification-demo/blob/main/results/report/report.md)）\
   29,684 条克罗地亚语零售商品名、10 个品类，主测试集 5,938 条。准确率 / macro-F1：TF-IDF+LR（20,777 条标注）96.7% / 0.916，BERTić 96.5% / 0.913，OpenAI Decisions（`gpt-6-luna`）95.4% / 0.883，Haiku 5.5 94.0% / 0.860，**Jev 1.14.0 93.8% / 0.845**（ECE 0.0163 全场最低，中位延迟 166 ms，每千条 $0.029），Qwen3.8 27B 92.5%。McNemar + Holm：两个有监督基线都显著胜 Jev，Luna 胜 Jev，Jev 与 Haiku 不可区分（p=0.62）。
   - **换成「测试品牌训练里没见过」的切分（5,934 条）顺序翻转**：Jev 94.32% 显著胜 TF-IDF 92.74% 与 BERTić 92.05%，Luna 95.25% 仍居首。
   - TF-IDF 约需 5,000 条标注才追平 Jev / Haiku；错误率 ≤1% 时可自动处理的覆盖率 Jev 71.9%、TF-IDF 89.7%、Haiku 52.8%；Jev 置信度 ≥0.9 覆盖 84.6%、错误 1.95%。小类「health」（29 条）Jev 精确率仅 0.30。见 [踩坑 #48](../guides/gotchas.md)。

2. **[ai-nexus-jp/jev-vs-decision1-benchmark](https://github.com/ai-nexus-jp/jev-vs-decision1-benchmark)**（**10-26 至 10-27**；日文）\
   80 条日文客服咨询（4 组 × 20：常规 / 多意图 / 讽刺与间接表达 / 越界与注入），分到「计费 / 合同 / 技术 / 其他」。CSV 核对：`jev-1.14.0` 77/80（96.2%），Microsoft Foundry `microsoft-decision-1` 72/80（90.0%），10 条分歧；平均延迟 218 ms vs 323 ms。多意图 100% vs 85%、讽刺 95% vs 80%；**越界 / 注入组反过来** Jev 95%、Decision-1 100%——Jev 唯一高置信错误是「你是优秀的 Python 程序员……斐波那契」被判成技术（0.88），Decision-1 判「其他」0.999。作者观察 Decision-1 不确定时倾向退回 `other`。题量小，适合当日文场景的起步对照。

3. **[rickcrawford/jev-relevancy](https://github.com/rickcrawford/jev-relevancy)**（**10-25 建仓、10-26 更新**；[docs/results.md](https://github.com/rickcrawford/jev-relevancy/blob/main/docs/results.md)）\
   ESCI 500 条查询、482,105 个商品、turbopuffer 混合检索 top-50。**当重排器**：nDCG@10 voyage rerank-3 0.463、`jev-1.13.0` 0.452、zerank-2 0.441、cohere v3.5 0.436、不重排 0.367；Voyage 领先 0.011 不显著（区间 −0.022 至 0.000，p=0.08）。**当评审**（200 对人工标注）：Jev 1.13 精确一致率最高，比 Gemma 高 0.080（区间 +0.005 至 +0.160），kappa 区间重叠；对 8 套配置排序，28 对里 26 对与人工一致。**1.14 vs 1.13**（3,692 对）：一致率 +0.031、kappa 0.471 vs 0.436，重排持平——「更好的评审，同样的重排器」。另记：**评审给自己重排的结果打分会偏高**（Jev 给 Jev 重排结果 0.983、Gemma 给自己 0.987），作者因此排除自评；否定词审计发现人工标签本身多处有误；文档从 800 字符放到 4,000 字符几乎无提升（0.600→0.606）。作者提醒 ESCI 可能在训练数据中。见 [踩坑 #49](../guides/gotchas.md)。

4. **[finic-ai/fraud-benchmark-vehicle-claims](https://github.com/finic-ai/fraud-benchmark-vehicle-claims)**（**10-27**；配套 [博客](https://finic.ai/blog/decision-models-xgboost-insurance-fraud) 10-26）——**厂商测试**：Finic 卖自家模型 Grayson，结论有利益相关。\
   Oracle 公开的 1,782 条车险理赔（923 条欺诈、27 个字段），8 个是 / 否问题喂 `jev-1.14.0`，把概率作为特征加进 XGBoost。12 次 5 折交叉验证 AUC：纯 XGBoost 0.798，+Jev 0.796（12 次里 4 次更好），+Grayson 0.805（10/12）。缓存了全部答案，不用 key 也能重跑；博客里的金额是假设值。与上期 ClaimSignal（另一份车险数据、零样本 AUC 0.423）方向一致：**编码好的表格字段上，Jev 的问答特征没给梯度提升树增加信息**。

5. **[ilanvys/jev-mekomil-study](https://github.com/ilanvys/jev-mekomil-study)**（**10-27**；希伯来语；[结果页](https://ilanvys.github.io/jev-mekomil-study/)）\
   53 道希伯来语问题 × 3 轮。路线 1 只用 Claude Sonnet 5.5 自己找 skill；路线 2 先由 Jev 三次调用判断该用哪个 skill，再交给 Claude。需要 skill 的题（每路 120 次）：拿到 skill 的中位时间 5.1 s → 1.5 s，Claude 轮数 4.1 → 1.0，选对率 90% → 92.5%。**不需要 skill 的 13 题里有 9 题路线 2 更慢**。局限作者自述：路由是在同一批题上调出来的；路线 2 会把用户问题发给第三方。

6. **[vincyberx/skejja](https://github.com/vincyberx/skejja)**（**10-26**；v0.1.0，57M 参数本地 System One 模型，PyPI 可装）\
   MASSIVE 意图集 choice 0.873（未见意图 0.741），是 / 否 AUROC 0.961，树莓派 4 上 choice 延迟 380 / 182 ms。README 把短板写得很清楚：真实语音助手 5 路路由仅 0.589；长输入 AUROC 0.79；S1MB 推理题接近随机；未见题型的是 / 否 ECE 0.150，给 64 个样例后降到 0.041。适合当「端侧小模型能做到哪」的参考，不是 Jev 替代品。

## 论文（窗口内新出 + 补记）

- **[arXiv:2610.34875 · RubriX](https://arxiv.org/abs/2610.34875)**（**10-26**；CobuildX，有利益相关）：LoRA 编码器做非自回归 rubric 评审，在留出 rubric 上精确准确率 75.4%，Jev 57.1%、Qwen3-8B 评审 49.8%；8 个人工标注集上多数与 Jev 相差 6 个点以内，但 Jev 在两个集上领先更多、平均排序最好。level 描述从 10 增到 3,000 token 时，Jev 延迟（扣除估算网络时间）从 44 ms 涨到 211 ms，RubriX 约 28 ms 不变。
- **补记 [arXiv:2610.26035 · Decision4Rec](https://arxiv.org/abs/2610.26035)**（Bari / Magdeburg；[代码](https://github.com/marcopoli/decision4rec)）：推荐重排里，**原版 Kev-4B 对 SASRec 候选的帮助和随机打乱差不多**；用真实选择训练过的 Kev-0.8B 在 15 个设置里 11 个胜过原版 `jev-1.13.0`、其余不输；收益大部分来自候选池与残差排序器，不是决策模型。另测得同一批 1,200 个请求隔几小时重发，Jev 只有 0.3–0.7% 的答案完全相同、首选变了 7%。
- **补记 [arXiv:2610.17820 · Same Attack, Different Judge](https://arxiv.org/abs/2610.17820)**（南开，10-13）：规则明确的输入审核上 Jev 最抗攻击（一句「为什么有人会这样问」只绕过 9%，GPT-6 Astra 56%）；但钓鱼邮件这种整体判断题，伪造字段绕过 19–29%，无攻击时 Jev 只识别 62%（GLM 评审 77–81%），且误拦良性请求最多（27%）。
- **补记 [arXiv:2610.25553 · Narrow Decision Models](https://arxiv.org/abs/2610.25553)**（10-18）：提出与 Jev 同接口、按单一机构训练的小型决策模型架构（选项顺序不变、问题互相独立），法院文书路由首个实例与生产中的 LLM 分类器一致 91%；完整结果留给后续论文。
