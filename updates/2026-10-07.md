覆盖窗口：约 **2026-10-06 10:20 Asia/Shanghai** 之后至本稿（约 **2026-10-07 10:10 Asia/Shanghai**）。对照已落地的 [2026-10-06](2026-10-06.md) 与 [2026-10-05](2026-10-05.md)；**不重复**已列工具、评测与中文深链。本期另补记三家窗口前上线、此前 dig 漏掉的托管 / 开放竞品（Databricks、Inception、Perplexity）。星标取自 2026-10-07 上午公开页面；性能与准确率均为原作者 / 厂商数字，本仓库未独立复现。

## 竞品补记：三家大厂同形 API（均在 09-30 至 10-02 上线）

继 [10-05 Cloudflare Clef](2026-10-05.md) 与 [10-06 阿里云百炼](2026-10-06.md) 之后，System One 形态已经成了「多家可换」的接口：

1. **[Databricks `ai_decide`](https://www.databricks.com/blog/introducing-aidecide-make-fast-decisions-your-governed-data)**（Beta，博客 **2026-09-30**；[SQL 文档](https://docs.databricks.com/aws/en/sql/language-manual/functions/ai_decide) · [REST 文档](https://docs.databricks.com/api/ai-functions/v1)）  
   以 SQL 函数 `ai_decide(state, questions [, options])` 直接跑在治理数据上，也有 REST 实时调用；题型同为 `noul` / `choice` / `score`，`choice` 选项 1–255 个，`score` 2–10 级。官方博客写明「对已在用 TypeSafe API 的团队直接兼容」。要求 Databricks Runtime 15.4 LTS+，不支持 SQL Classic。适合「整表打标签 / 路由」这类批量场景，而不是 agent 循环里的单次调用。

2. **[Inception Mercury Decide](https://openrouter.ai/inception/mercury-decide:free)**（OpenRouter 标注上线 **2026-09-30**；免费档）  
   扩散模型厂商 Inception 的决策模型，只经 OpenRouter 的 Decisions API（`POST https://openrouter.ai/api/alpha/decisions`，模型 `inception/mercury-decide:free`）提供，**不走** chat completions SDK。页面写 32,768 上下文、「每秒最多 14 个决策」、输入输出均免费但有免费档限速，不适合直接上生产。窗口内已有接入：[apatlasdev/fast-decide-compaction](https://github.com/apatlasdev/fast-decide-compaction)（Claude Code / Codex 插件，用它对旧工具调用逐条判「还需要吗」做上下文压缩，保留项原文不改）。

3. **[Perplexity pplx-decider-v1-27b](https://huggingface.co/perplexity-ai/pplx-decider-v1-27b)**（Apache-2.0；HF 发布约 **2026-10-02 05:24**；[Decisions API 文档](https://docs.perplexity.ai/api-reference/decisions-post)）  
   **开放权重 + 托管 API 双轨**：Qwen3.8-27B 微调，支持文本 / JSON / 图片 state，`POST /v1/decisions` 一次 1–128 个问题、输入上限约 262,144 token，输入 $0.04 / 百万 token、输出免费；本地需约 49 GiB 显存。模型卡 11 项基准自报总分 85.71% 对 Jev 84.51%，但**分项并非全胜**：BBH（82.80 vs 94.27）、WinoGrande（83.30 vs 90.70）、JevBench public hard（70.30 vs 73.27）仍落后 Jev，领先主要在 RAGTruth、FinancialPhraseBank。数字由 Perplexity 经自家 API 测得。Vercel AI SDK 侧已有 [PR #22185](https://github.com/vercel/ai/pull/22185) 为 Perplexity provider 加 `decisionModel`（合并状态以仓库为准）。

**对使用者的影响**：同一份 `state + questions` 现在至少能在 TypeSafe、OpenRouter、Cloudflare、阿里云、Databricks、Perplexity 之间切换，但上下文上限、问题数上限、是否截断（见 [踩坑 #30](../guides/gotchas.md)）各不相同；换后端前先用末尾哨兵事实和自己的标注集各测一次。跨厂商对照的社区地图可看 [aaddrick/building-with-decision-models](https://github.com/aaddrick/building-with-decision-models)（非官方 skill，按「托管 / 数仓 / 本机」整理各家差异并链接 450+ 项目，约 10-07 新建）。

## 值得一看的工具 / 开放模型（优先）

1. **[tsale/jevline](https://github.com/tsale/jevline)**（约 17★；约 **2026-10-06 09:01** 创建；[在线版](https://jev-incident-timeline.vercel.app/)）  
   安全事件溯源：从一个已确认恶意的进程 / 地址 / 账号出发，按遥测里的父子、注入、落地执行、网络与登录链接逐轮问 Jev「是否属于同一事件」，阈值 0.8、±0.05 进复核。作者在一台 Windows 主机六天真实遥测（约 101 万条、2.3 GB）上对照分析师攻击链：Jev 找到 41 个进程中的 40 个、误判 1 个、21 s、约 $0.11；同引擎换 GLM 5.3 Flash 作答找到 41 个但误判 8 个、32.6 分钟、$1.06。问题数随事件规模增长（337–1,123 次）而非随日志量增长。作者明确写「实验性，不是经过验证的检测器」，分数衡量的是**与事件的相关性**而非恶意与否。复现脚本 `engine/bench/compare.ts`。

2. **[agentmessier-ai/messier-one](https://github.com/agentmessier-ai/messier-one)**（约 **2026-10-06** 创建；权重 [agentmessier/messier-one](https://huggingface.co/agentmessier/messier-one)，**CC-BY-NC-4.0，非商用**）  
   Qwen3.5-4B 微调的开放决策模型 + 兼容 `/v1/systemone` 的 vLLM 服务端，单张 24 GB 卡可跑，`choice` 最多 255 个选项。作者用 JevBench 官方 runner 在 231 道公开题上自测 197/231（easy / standard 全对，hard 69.4%），RTX 5090 p50 约 46–95 ms，并已提交 [JevBench #194](https://github.com/fstandhartinger/jevbench/issues/194) 申请上榜。作者自述 hard 档训练数据是「照 JevBench hard 题型写的」，虽称未用任何原题，分数仍需等榜单维护者在保留集上核验。相对 10-06 jiwo / SynACK Decide：本项是 **4B 档、但许可不能商用**。

3. **[dexmac221/system-switch](https://github.com/dexmac221/system-switch)**（Apache-2.0；约 **2026-10-05 21:11** 创建，补记；论文 arXiv 链接待补）  
   「快决策模型什么时候该停下来想」的闭环研究：System One 模型在 [doomLaya](https://github.com/azalio/doomLaya) 里玩 Doom 做每一步决策，门控在低置信、无进展、循环时把一步交给 Qwen3.6-35B-A3B 视觉推理模型。900 道保留题上：零样本决策模型系统性偏爱「捡东西」（错误中出现率为随机的 1.6–1.8 倍）；**打乱选项顺序**会让 Strands Decider 指令准确率从 0.59 掉到 0.38；把 30% 决策转给推理模型的收益与执行者的 AUROC 高度相关（秩相关 0.87），但最敏感的 Laya base（AUROC 0.89）在同一类别内接近随机。闭环 33 局里没有一局走到出口。负结果写得很完整，数据与逐题记录全部公开。
