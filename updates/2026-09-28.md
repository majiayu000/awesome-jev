## 值得一看的工具（优先）

1. **[ollaya-dev/ollaya](https://github.com/ollaya-dev/ollaya)**（约 702★；[ollaya.dev](https://ollaya.dev)）  
   「决策模型界的 Ollama」：`pull` / `run` / `serve` 本地跑开源决策权重，并提供与 TypeSafe **wire 兼容**的 `POST /v1/systemone`（官方 SDK 可改 `TYPESAFE_BASE_URL=http://localhost:11435`）。模型库含 `winnow:e4b`（作者自报 typed-decisions 约 0.722 vs Jev 0.738）、`laya` 路由、`kev` / `jevk5` / `von` / NLI / GLiClass 等；另有 MCP 与 `ollaya-decisions` skill。相对 09-23 Laya-ultrafast / 09-24 `laya-server`：本项是**统一本地运行时 + 模型目录**，不是单一权重移植。

2. **[jaredpalmer/kev](https://github.com/jaredpalmer/kev)**（约 7430★；HF Space 可试）  
   Jared Palmer 的开源 System One 族：Qwen3.5/3.8 上的 Choice / Score / Noul，校准温度默认出厂；API 对齐 `/v1/systemone`，TypeSafe Python SDK 可指到本机。型号 0.8B→27B；作者表上 Kev-27B 在「新来源」准确率约 0.848（Jev 开发集约 0.857）——**非受控架构对比**。09-22 `jevals` 仅旁注「本地 Kev·Laya」作后端，本轮单列。相对 AnyJev / AgentJev / JevK5：可训练、可部署的**完整开放族**。

3. **[dzhng/jevgrep](https://github.com/dzhng/jevgrep)**（约 789★；npm `@dzhng/jevgrep`，CLI `jg`；约 2026-09-26 起公开）  
   给 coding agent 的语义入口：用自然语言问仓库「某能力在哪」，Jev 在文件夹 / 文件 / 声明上做相关性判断，stdout 返回文件、阅读线索与原文摘录；附 `jg skill`。作者自报十题 SWE-bench 对照：与基线同完成 8/10、成本约低 30%。与 09-21 [`kyu1204/jgrep`](https://github.com/kyu1204/jgrep)（npm `jevgrep`）**不同仓**：本项偏 agent 发现入口 + skill 分发，对方偏管道语义 grep / CI diff。

4. **[aaddrick/building-with-typesafe-jev](https://github.com/aaddrick/building-with-typesafe-jev)**（约 87★；约 2026-09-26）  
   非官方 coding-agent skill：教代理按 typed questions / 校准置信度设计，并链到 **150+** 社区项目（按形状分类 + 代码草图）。可装 Claude Code / Codex 等；作者写明不同于官方 [typesafe-ai/skills](https://github.com/typesafe-ai/skills)。用途是「别把 Jev 当又一个 chat 模型」，不是又一个 MCP 壳。

## 评测 / 负结果 / 官方侧（增量）

1. **[MLflow · Can Jev replace your LLM judge?](https://mlflow.org/blog/jev-llm-judge/)**（Yuki Watanabe，2026-09-22）  
   30 条人工标注的 MLflow 技术问答：Jev 1.13.0 与人类一致 30/30，中位延迟约 369 ms，估约 $0.0247 / 1k 次；与 GPT-5.6 Terra/Luna 同判决、更低成本延迟。强调样本窄、Jev **无 rationale**（迭代期仍宜文本 judge；大规模监控可先 Jev）；二值 Noul 不能弃权时改用带 `unsure` 的 Choice。相对已记的 LangChain / Langfuse / Arize：本项是 **MLflow scorer 形态** 的厂商实测。

2. **[arXiv:2609.26550 · JEV-as-a-Judge: Accept When Confident, Escalate When Unsure](https://arxiv.org/abs/2609.26550)**（CMU 等，2026-09-21）  
   与十余个生成式 / reward-model judge 对比 + 盲审：普通偏好与有证据事实性上，Jev 距最强 LLM judge 约 3 个百分点内、费用约 0.36%；**JudgeBench / 需核对推导**与**华丽错误答案（style-adversarial）**差距拉大到约 9–20 点。错误集中在低置信度区；冻结 cascade「自信接受、不确定升级」可保留约 99% 对照准确率并降费。阈值需本地验证、无参考散文近随机。方法密度高，宜作 judge 工作负载边界清单。

3. **[arXiv:2609.27678 · Same Scores, Different Decisions…](https://arxiv.org/abs/2609.27678)**（ContractNLI）  
   合同多假设推理：Jev 成本与中位延迟最低，托管 LLM 基线准确率更高；**平均准确率排名 ≠ 跨请求条件始终正确排名**；修正与回退可在总分里互相抵消。提醒：合同类任务别只报一个 aggregate。

4. **[OpenRouter cookbook · Cut LLM Cost with a Jev-Verified Cascade](https://openrouter.ai/docs/cookbook/evaluate-and-optimize/jev-verified-cascade)**  
   可跑配方：便宜模型起草 → Decisions API（`/api/alpha/decisions`，注意 SDK 需单独 `serverURL`）用 Jev 验「是否被检索片段支持」→ 仅失败时升级 frontier。50 题示例：与全量 Astra 同为 0 错答，成本约 7%。与 arXiv cascade 同思路、偏工程落地。

5. **中文负结果 / 边界：[Jev 的边界 · BMPI](https://www.bmpi.dev/dev/jev-boundary/)** + [V2EX 帖](https://www.v2ex.com/t/1243613)（约 2026-09-21 起可核）  
   Free4Chat Arena / Live View 实验后**未接入** Jev：高频控制环里 Scripted Bot 更稳；直连 API p50 约 344 ms、经 Cloudflare Gateway warm p50 约 635 ms——对「反射层」仍偏慢。提炼三分法：**规则能写死 → 代码；规则模糊但候选明确 → Decision Model；连候选都要创造 → 生成模型**。成功 demo 往往先由 harness 整理 state/候选。属作者口述 + 方法文，非榜单复现。
