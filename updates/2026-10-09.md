## 补记：更大样本的 OpenAI Decisions ↔ Jev 对照（10-07，10-08 未收）

**[Nexus Agent · OpenAI Decisions API vs Jev](https://agent.nexus/blog/openai-decisions-api-vs-jev)**（**2026-10-07** 发布；自家助手护栏上的 8 道真实检查）

- 规模：三轮计时 + 一轮 token 记录，**超过 9,000 次调用**（计时 6,624；标注评测 2,155 例）。同一套题分别打 TypeSafe `jev-latest` 与 OpenAI `gpt-6-luna` Decisions。
- 质量：错误 221（Jev）对 233（Decisions），95% Wilson 区间几乎完全重叠；去掉阈值后 8 道题里 7 道 AUC 打平，仅「日志行是否说到工作」一项 Jev 略优。作者自述**自己在生产里用 Jev**，且阈值未为 OpenAI 重调，结论需打折读。
- 速度：中位几乎一样（269 vs 268 ms）；**p99 差 2.8×**（526 vs 1,469 ms）。超过 1 秒的调用：Jev 3/2,208，Decisions 95/4,416。
- 价格：牌价输入 $0.042 vs $0.10 / 百万 token（约 2.4×）；按实测 token 每千次约 $0.11 vs $0.22（约 2.1×）。探测发现 Decisions **每多一道是非题约多计 144 token**，8 题同 call 时可达约 6.8× Jev 成本；Jev 侧约有固定 ~260 token / call。
- OpenAI 仍赢在**图像输入**与合规选项；本文未测图像。相对 [10-08 mateusfonsek 葡语 450 例](2026-10-08.md)，这是目前公开最大的英文本地护栏对照。

**对使用者的影响**：文本护栏场景别只看中位延迟；按 p99、按「每 call 问题数」估账单，并在自己的标注集上重调阈值后再比。

## 竞品：Liquid 开源 d1-3B / d1-omni-600M（10-07）

**[Liquid AI · Open d1](https://www.liquid.ai/blog/d1-open)**（**2026-10-07**；权重 [d1-3B](https://huggingface.co/LiquidAI/LFM2.5-VL-3B) / 见官方链接；[HF 博文](https://huggingface.co/blog/LiquidAI/open-d1)）

- **d1-3B**：从 LFM2.5-VL-3B 训出的开源决策模型，文本 + 图像；厂商报 Decision Index v0.2.1 public **48.57**，称领先所有 10B 以下、与 12× 参数的 Decider 35B-A3B 同档；RTX 4090 单题 **8 ms**，Jetson Orin Nano **50 ms**，支持 llama.cpp / NVIDIA 全家桶。
- **d1-omni-600M**：实验档，文本+图或文本+音频；同指数 **15.95**，厂商写明是早期研究发布。
- 与 Jev / OpenAI Decisions 的关系：开源、可边缘部署、原生多模态；指数与托管 API 不是同一套评测，**不要直接拿 48.57 和 Jev 的 Decision Index 57.9 加减**。窗口内日文媒体亦有跟进（见跳过列表中的 GIGAZINE 转述）。

## 独立评测与负结果（优先）

1. **[takeshiue/decisions-benchmark](https://github.com/takeshiue/decisions-benchmark)**（约 **10-08 19:46 UTC** 公开；[结果页](https://takeshiue.github.io/decisions-benchmark/) · [长文](https://takeshiue.github.io/decisions-benchmark/article.html)）  
   日文作者自编 **文本 120 题 × 3 轮**（知识 / 文章判断 / 计算 / 情境 / 虚构经费规程）对比 Decisions 与 Jev：Jev **95.0%**（342/360）、中位 302 ms；OpenAI **91.7%**（330/360）、320 ms。差距主要来自**计算题**（OpenAI 73.3% vs Jev 93.3%）；知识与文章判断两侧接近满分。规程判定双方都有「会餐人均算错档」的共同错误。另用 **图像 10 题 × 3** 对比 Decisions 与同模型 Responses 路径的 Luna：Decisions 30/30、中位约 754 ms；普通 Luna 27/30、约 2.5 s。题面、答案与逐次结果全公开。注意：计算题本就落在官方 jaggedness 的弱项区，规程题含算术，数字不宜外推到你的业务集。

2. **[armando-token/industrial-selection-bench](https://github.com/armando-token/industrial-selection-bench)**（约 **10-08 23:02 UTC**；MIT + 数据 CC BY）  
   工业选型试点：三份真产品、五本厂商 PDF（186 页）、**12 道保留案 × 3 次 = 180 次打分**，对照 JEV 结构化管线、RAG、抓取 agent、同管线换 Gemma 4 裁判、无模型规则基线。作者结论很克制：**最好引擎只做对 2/12**，各引擎置信区间重叠；JEV 管线比 RAG **快约 14.6×**，但有一例应拒却误批（规则基线也错在同一案）。金标经 AI agent 核对而非人类专家，作者标明 pilot。适合当作「说明书选品」负结果样本，而不是能力上限声明。

3. **[JevOut](https://arxiv.org/abs/2609.30243)**（USC 等；[项目页](https://xzx34.github.io/jevout/)；**Agenthon @ NeurIPS 2026** 海报接收，作者 **10-09** 公开宣布）  
   与 [踩坑 #32](../guides/gotchas.md)「自称管理员」不同：这里加的是**看起来自然、不改题面/选项/金标**的短背景句。在 64 次接受评估预算内，Jev 上 **61.4%**（312/508）的「原本答对」被定向翻到事先固定的错误选项；其中 45.1% 错误选项概率 ≥0.7。人工抽检 250 条成功上下文，91.6% 被多数标注员判为自然且不改变金标。跨模型迁移翻转率约 21–48%。见 [踩坑 #33](../guides/gotchas.md)。
