## 独立评测与负结果（优先）

1. **[mmikaildemir/commit-or-abstain](https://github.com/mmikaildemir/commit-or-abstain)**（**10-21**；论文《Commit or Abstain? System One Decision Models, LLMs, and Missing Legal Authority》的代码、数据与全部模型输出，[`final_stats.json`](https://github.com/mmikaildemir/commit-or-abstain/blob/main/final_stats.json) 可离线重算）\
   在 CaseHOLD 全部 5,314 道法律判例题上加一个「放弃」条件：其中 1,670 题把正确判例换成另一案件的相似判例，并加第六个选项「以上都不适用」。4 个决策模型 × 6 个生成式 LLM：
   - 原始条件准确率：Gemini 3.8 Flash 0.882、pplx-decider v1.2 0.881、d1-ultra 0.849、**Jev 1.14 0.783**、GPT-6 Luna 0.776、Luna Decisions 0.722。
   - 正确答案不在选项里时**仍硬选一个错的**比例：Jev 1.14 **30%**（全场最低），d1-ultra 41%，pplx-decider 57%，Claude Haiku 5.5 81%，GPT-4o-mini 86%。
   - 反过来，正确答案明明在、却选了「都不适用」：Jev 1.14 **26%**（全场最高），其余决策模型 2–10%，LLM 2–8%。也就是说 Jev 在这个设定里的「谨慎」是用大量误弃换来的。
   - 每千题成本：决策模型 $0.01–0.06，LLM $0.07–0.78。论文还做了模型组合策略、污染检查，并把 Jev 概率蒸馏进 Qwen3-8B。见 [踩坑 #46](../guides/gotchas.md)。

2. **[dwayo-ai/system-one-decision-bench](https://github.com/dwayo-ai/system-one-decision-bench)**（**10-22**；Apache-2.0；[REPORT](https://github.com/dwayo-ai/system-one-decision-bench/blob/main/results/REPORT.md)；[博文](https://dwayo.ai/blog/jev-system-one-decision-model-benchmark/)）\
   `jev-1.13.0` 对 Claude Haiku 5.5（**关闭思考、max_tokens=128**，作者明说这不是 Haiku 默认行为：开思考时大量调用把预算花在思考上、没给答案），阈值规则事先写定、带 bootstrap 置信区间。BANKING77：Jev 0.790 vs Haiku 0.750；10 类子集两者持平（0.955 / 0.958）；护栏任务 0.818 vs 0.790。实测延迟 p50 约 350–370 ms、p95 460–680 ms，每千次 $0.014–0.043。**Jev 不确定时转给 Haiku 的级联**：BANKING77 上只转 5.4%，准确率比单用 Haiku 高 5.4 个点、成本 0.45 倍；在 10 类和护栏任务上级联几乎没有增益——好处取决于任务难度，不是普遍规律。

3. **[sdivye92/evaluating-jev-as-a-judge](https://github.com/sdivye92/evaluating-jev-as-a-judge)**（**10-22**）\
   「Jev 能不能替代 LLM 评审」的可复跑框架：`jev-1.13.0` 对 Claude Haiku 5.5 / Sonnet 5.5，任务包括 GSM8K 近似错误答案、MBPP 单处变异代码（以测试执行为标签）、长度匹配的 HaluEval 和 HelpSteer2 0–4 分人类评分。仓库已提交逐调用日志 `results/calls.csv`，但 README 还没写结论，**先收方法，结果待补**。

4. **补充对照 · [casteruee/aegis-market-lab](https://github.com/casteruee/aegis-market-lab)**（**10-22**；中文报告 [`results/REPORT.md`](https://github.com/casteruee/aegis-market-lab/blob/main/results/REPORT.md)）\
   OKX BTC-USDT 1 小时 K 线，同一回测引擎、含手续费和滑点、下一根开盘成交，并用 freqtrade 逐笔交叉核对（40/40 笔一致）。样本外：双均线 −6.27%、`jev-1.13.0` −6.06%、**不给 Jev「不操作」选项、强制三选一反而 −2.45%**，三者都输给买入持有 +3.79%。与上期 BTC 预注册负结果方向一致：行情择时不是 Jev 的强项。

## 开放替代品（均为作者自报，对比条件不对等）

- **[leofmarciano/groot](https://github.com/leofmarciano/groot)**（**10-22**；Apache-2.0；[权重](https://huggingface.co/marcyano/Groot-1-S)）：149M 参数（mmBERT-small 改造），讲 System One 请求格式，选项注意力做了分块遮罩、对选项顺序严格不变。作者在 A10G 上的表：2,000 道 typed decisions 75.2% vs Jev 73.7%，分类数据集（CLINC150 89.0% vs 74.4%、DAIR Emotion 94.8% vs 60.0%）大幅领先，但 **BoolQ 67.6% vs 90.6%、ASSIN2、HateBR 落后**；长文 64k 针检 96% vs Jev 100%。注意 Groot 在这些数据集的训练切分上训练过，Jev 是零样本，且 Jev 延迟含公网往返。
- **[decido-ai/decido](https://github.com/decido-ai/decido)**（**10-22**）：Gemma 4 26B-A4B 的 LoRA，8-bit GGUF 跑 CPU，兼容 `POST /v1/systemone`、可直接接官方 SDK。六组基准均值 85.38 vs Jev 1.13 **官方公布值** 83.85，但**去掉各基准公开训练集后降到 82.04**，即低于 Jev；Jev 一侧不是同一 harness 实跑。M4 Pro CPU 上 1k token + 5 题约 4.1 s（Jev 托管约 0.3 s），需约 30 GB 内存。
- **[sku10/cpu-decision-bench](https://github.com/sku10/cpu-decision-bench)**（**10-22**）：4B 决策模型在 CPU 上值不值得跑的自测脚本。Ryzen 7 5800X 单请求 p50 820 ms，并发 1→8 吞吐**平的**（0.99→0.95 req/s），i5-7600K 约 3.9 s：瓶颈是内存带宽，加核没用；可用 L3 能装下一层（Q4 约 64 MiB）才有优化空间。给想本地部署 Jev 替代品的人一个现实预期。

## 应用里的可核对数字

- **[luv-agarwal/ck-browser](https://github.com/luv-agarwal/ck-browser)**（**10-21**；MIT；仅标准库）：自然语言写的浏览器 E2E 检查，每一步元素定位 / 页面是否稳定 / 文本是否出现都交给 Jev 读 DOM 快照判断（约 180 ms 一次）。作者在三个真实 web 流程上（两边都 9/9 通过）：比「LLM agent 每步一回合点 chrome-devtools」快 11–17 倍、单次便宜约 200–380 倍（约 15 s、$0.002 vs 171–257 s、$0.31–0.54）。比较对象是 agent 循环，不是直接写 CDP 脚本。
