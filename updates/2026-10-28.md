## 独立评测与负结果（优先）

1. **[Guilherme-pxt/hybrid-search-rag](https://github.com/Guilherme-pxt/hybrid-search-rag)**（**10-27**；README「Jev (TypeSafe) as a reranker」一节）\
   合成内部文档库（同一政策分地区、同一规格分档，专门制造「找对家族、找错兄弟」的近重复），135 道金标题（110 可答 / 25 不可答）。BM25 + LSA 向量 RRF 融合后 Recall@1 只有 0.564；本地 `qwen2.5:7b` 逐条打分重排到 0.900，但每题 6.66 s。换成 `jev-1.14.0`：fused top 20 每段一个 noul，一次请求——**Recall@1 0.918、nDCG@10 0.922，每题 0.25 s，每千题约 $0.17**，与 LLM 的差距在噪声内（Recall@1 +0.018，区间 [0.000, +0.045]）。金标段落中位 noul 0.97、其余 0.02；25 道不可答题没有候选超过 0.7（作者提示可做检索侧「不知道」门，但未实测）。
   - **把 Jev 排序和原融合排序再做一次 RRF，反而吐回大半收益**：Recall@1 0.654（比 Jev 单独低 0.264，区间 [−0.345, −0.182]）。作者解释：第一阶段恰好就是错在兄弟文档上，RRF 给它和 Jev 同样的票。见 [踩坑 #50](../guides/gotchas.md)。
   - 预先固定 N=8 的「Jev 先筛 + LLM 精排」级联保住 0.900、LLM 时间省 61%，但仍不如 Jev 单独又快又好。

2. **[finic-ai/fraud-benchmark-lending-club](https://github.com/finic-ai/fraud-benchmark-lending-club)**（**10-26 建仓、10-27 更新**；[博客](https://finic.ai/blog/decision-models-xgboost-loan-default)）——**厂商测试**：Finic 卖自家模型 Grayson，结论有利益相关。\
   上期车险仓的姊妹篇。Lending Club 约 12.6 万笔带借款人自述的贷款，按发放时间切分，测试集 3,000 笔；27 个核贷问题事先写好。ROC-AUC：XGBoost 0.681，+TF-IDF 0.684，**+Jev 0.687（+0.006，区间 [−0.003, +0.016]，不显著）**，+Grayson 0.689（+0.008，区间 [+0.001, +0.016]）。增益主要来自读借款人自述文字（如「是否描述当前财务困难」）。与车险那篇合看：**结构化字段之外有自由文本时 Jev 特征才可能有一点用，且这次仍未显著**。答案已缓存，不用 key 可重跑。

3. **[nob-git-dev/gemma4-typed-decisions](https://github.com/nob-git-dev/gemma4-typed-decisions)**（**10-27 建仓、10-28 出结果**；日文；[RESULTS.md](https://github.com/nob-git-dev/gemma4-typed-decisions/blob/main/RESULTS.md)）\
   用官方 `gemma-4-26B-A4B-it`（FP8）取最后隐状态、只投影到候选 token 的输出行，0 生成 token，实现 Noul / Choice / Score 的 `/v1/systemone` 兼容接口；作者声明未用 Jev 复刻代码、派生权重或 Jev 生成的标签。英文未用过的公开测试 3,300 对、与官方 `jev-1.14.0` 成对比较：准确率 **78.0% vs 79.9%**（Noul 90.9 / 93.1，Choice 83.9 / 86.6，Score 56.1 / 56.3），平均 HTTP 123 ms vs 149 ms（本地 GB10 对比云端，含网络）。事先设定的「相对损失 ≤5%」门槛通过。但 **Brier 0.105 vs Jev 0.073，概率未校正**，日文与校准等价性都不在结论范围内；需要约 116 GiB 空闲内存。适合当「开放权重能离 Jev 多近」的参考，不是替代品。
