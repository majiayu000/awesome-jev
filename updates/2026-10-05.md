## 竞品补记：Cloudflare Clef / Clef-Flash

## 值得一看的工具（优先）

1. **[madisonrickert/jev-permission-gate](https://github.com/madisonrickert/jev-permission-gate)**（约 24★；约 **2026-10-03**）  
   Claude Code auto mode 前置门：shell 语义解析的黑名单先挡，再让 Jev 一次答 8 个 yes/no，按阈值 allow / deny / 交回内置分类器。作者在 7,860 条标注工具调用上**先在 dev 定阈值、再一次性跑封存 test**：3,664 条危险调用里 **1** 次不安全放行（`git reset --h`，已补进黑名单），1,699 条不该拒的只误拒 5 条；真实 agent 轨迹上约 **62%** 不用再走内置分类器，中位等待 164 ms 对 329 ms。相对 10-02 jev-llm-guard（通用 LLM 护栏）：本项是**具体 coding agent 权限门 + 封存测试集**的成品。

2. **[yinhong-zhou/jevdo](https://github.com/yinhong-zhou/jevdo)**（约 23★；MIT；约 **2026-10-02**；中文优先 README）  
   基于 DeepSeek Harness 的「Jev 调度、主模型兜底」agent loop：主模型把走通的操作沉淀为可验证 Action，下次由 Jev 先判断「是不是已经会了」再直接执行。作者三任务子集实验：复用轮主模型调用 24 → **0**、估算费用降约 **63–74%**；但含首轮积累的三轮合计仍比原生高约 **11%**，作者自己写明是小样本、非公开基准。相对 09-22 JevHarness 族：本项把**经验复用**而非单点门控交给 Jev。

## 评测 / 负结果 / 综述（增量）

1. **[ankushchadha/system-one-security](https://github.com/ankushchadha/system-one-security)**（约 **2026-10-04**；可重跑脚本 + 预先写下的预测）  
   引用核查场景下对 Jev 与 Clef / Clef-Flash 做五组安全实验：模型「相信 state」，改事实结论跟着变；托管 Clef 约 2,048 token 后的 state 静默丢弃，前置文本可把末尾证据挤出视野；指令式注入大多失败，但在 Jev 的 yes/no 上，state 末尾一句「标签已对调」几乎把所有正确结论压到 0.5 以下。部分结果因向厂商协调披露暂扣。相对 10-02 安全门控论文：本项是**跨厂商、可复跑的 state 投毒 / 截断**实验。

2. **[wuchengwei1996/jev-zh-tw-eval](https://github.com/wuchengwei1996/jev-zh-tw-eval)**（约 **2026-10-04**；繁中 README）  
   经 Ollama `/v1/systemone` 对开放模型 Plumb-4B 做繁中评测：MASSIVE zh-TW 2 / 8 / 26 选项约 96 / 93 / 81 分；台湾新闻按发布者类别约 66–72%；伪装备注注入 18 题中 7 题达成攻击者目标；批次从 4 题加到 64 题时单题平均概率漂移约 0.034 → 0.102。作者结论：**适合辅助分流，不适合单独做高风险自动闸门**。相对 10-02 Chinese-Jev（简中训练 + CJ-Bench）：本项是**繁中、本地、含对抗与批次漂移**的使用者视角评测。

3. **[arXiv:2610.02586 · Labels Override Definitions…](https://arxiv.org/abs/2610.02586)**（USC；约 **2026-10-01**）  
   四个开放决策模型、十一项任务 + 自建 PolicyBench：答案主要跟**选项标签**走而非定义——删掉全部定义准确率几乎不变，选项改名 A/B 反而 +0.15。根因定位在 prompt 渲染（laya 写 `{label}: {definition}`，von 只写定义），只改这一行即可让效应消失或出现；给出两次调用的自检法。相对 09-28 已收 2609.26758「选项名极性」：本项把锅从决策头**挪到了渲染层**，且有可操作的自检。

4. **[arXiv:2610.02267 · Fast Models, Slow Evidence…](https://arxiv.org/abs/2610.02267)**（约 **2026-10-01**；数据与代码 [David-DL-Space/sys1-eval](https://github.com/David-DL-Space/sys1-eval)）  
   11 个 agent 决策点、7,283 基础题 + 6,640 鲁棒性变体，配对比较 Laya 与 Jev：Jev 在 9 项上显著更准（+10.8 至 +46.0 pp），零样本模型路由两者都不超随机；Laya 选项倒序会改 30% 答案。难得的是**自审**：作者承认自己三处分析错误曾把节省 4.3% 报成 23.9%、把门控准确率当端到端质量（58% 对 98%）。

5. **[arXiv:2610.02076 · LLM2Jev](https://arxiv.org/abs/2610.02076)**（约 **2026-10-01**）与 **[AgentEra/system-one-benchmark](https://github.com/AgentEra/system-one-benchmark)**（约 **2026-10-02**；中英报告）  
   两项都在问「是不是非得用专门的 System One 模型」：前者称不训练的 Qwen3.5-4B 读编号 token 概率即可追平同骨干社区模型，微调主要帮弱模型和多选项路由；后者在 50 个合成任务上称关掉推理的 DeepSeek v4 Flash 准确率点估计更高、延迟更低，每千次请求贵约 $0.03–0.08（置信区间含零）。作为**反方证据**收录，场景都偏窄。
